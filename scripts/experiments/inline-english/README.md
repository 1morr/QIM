# inline-english：句中英文混輸值不值得做（M4 票 28）

- 日期：2026-11-15；機器：Apple M6（Mac mini，32 GB）、macOS 27.0.1；rustc 1.99.1。
- commit：M4 票 28 的分支（開工 `9ce368b`）。機制在 `aec9741` 進核心、預設關（門檻同一個 commit 寫進票）；結論見〈結果〉，之後的 commit 把機制刪掉，重跑要在 `aec9741` 上（見〈怎麼重跑〉）。
- 問題：一串輸入碼裡夾英文詞（「今日有meeting」）時，讓英文詞帶懲罰進 lattice，值不值得做。拼音靠「拆不成合法音節」認出英文，速成沒有這個訊號（速成每字 1–2 碼，幾乎每兩個字母都是合法碼），只能比語言模型分數，誤判風險高（brief §4.7）。採用門檻在票 28 的 Comments（看結果前寫、和機制同一個 commit），結論在 `docs/research/inline-english-2026-11-15.md`。

## 機制（`aec9741` 的核心裡預設關，之後刪掉）

`qim_core::Engine::with_inline_english(InlineEnglish { penalty, min_len, min_frequency })`：

- 英文資料包（`aosp-en-us`，AOSP LatinIME 的詞表）裡、整個詞都是方案的字母（a–y）、至少 `min_len` 個字母、頻率（AOSP 的 `f`，0–255）至少 `min_frequency` 的詞，碼剛好是它時多一條邊（`Engine::exact`，所以 lattice、只蓋住開頭一段的候選都有它）。
- 分數固定是 `−penalty`：不接字級 bigram、不加 β、γ、沒有學習加分；它後面的字前一字是英文字母，照語言模型「前一字沒有統計」的退回式算。
- 不容錯：鄰鍵讀法（M4 票 09c）換過碼才查得到的英文邊不收；不補全；有萬用鍵、分隔記號的碼不收。
- lattice 往回找邊的上限加到收得進來的最長英文詞（`with_inline_english` 時算一次）。
- `qim-bench` 的 `load_engine` 在環境變數 `QIM_INLINE_ENGLISH=<懲罰>,<最短長度>,<最低頻率>` 設了時打開它，所以 `cargo xtask bench --dev`、`--check` 照原樣量純中文集。
- 沒做：debug 面板的來源（借用「使用者詞」）、選了之後的學習（照一般的段學）、和規則 4 的整串英文候選分工（整串剛好是英文詞時，英文邊是一般的候選、照分數排，規則 4 的那個因文字重複不另列）。

## 量法

獨立的 crate（`Cargo.toml` 有空的 `[workspace]`），不在 repo 的 workspace 裡，`cargo xtask check` 不編它；路徑依賴 `qim-core`、`qim-bench`、`qim-databuild`。改程式後自己跑 `cargo clippy --release --all-targets -- -D warnings`、`cargo fmt --check`。

### 混輸句（收益）

- 來源：四個語料（粵語維基、中文維基、HKCanCor、Common Voice 粵語）轉換同 `cargo xtask data`，照標點與符號切開（空白不切；兩邊都不是英文字母的空白照樣切），留下只有連打字集的字、英文字母與空白、中英都至少有一個、沒有數字的段。這些句子首選字基準切句時整句丟掉（含英文字母），所以不在任何語料的 train 裡；但它們的中文片段在其他句子裡可能出現（例如「用 Python 寫」的「用」「寫」各自當一句進了 train），和首選字基準一樣不另濾。
- HKCanCor 是分詞的語料、詞直接接起來，相鄰的英文詞會黏成一串（`Hong Kong` → `HongKong`），所以它從分詞的詞接、英文詞之間補空格。
- dev、test 照首選字基準的 `split_of`（去掉空白後的句子的 sha256），每個語料每個切分取雜湊最小的最多 2,000 句。
- **偏書面**：dev 4,101 句、test 4,097 句，其中維基各 4,000 句，口語只有 HKCanCor 94／87 句、Common Voice 7／10 句。維基夾的英文最常見的是單一字母（`A`、`B`）與專有名詞（`ViuTV`、`Facebook`、`YouTube`），口語夾的有 `call`、`office`、`friend` 這類常用詞，所以這裡量到的收益不一定代表口語；口語的兩個語料另列，但句數少。
- 每個英文詞用的文字：英文資料包有它時是資料包的拼法（核心給的就是它，`Hong`、`DNA`），沒有時照原文；比對照首選字基準，文字要完全相同。

使用者怎麼打（`src/main.rs` 的 `Typist`）：

| 打法 | 中文 | 英文詞 |
| --- | --- | --- |
| 規則 4（基準，協調者同意） | 每段中文單獨打到上屏 | 規則 4 出得了（詞典有、3 個字母以上、只有 a–y）的單獨打、從第 2 位選（算 1 次修正）；出不了的按 Shift 直打 |
| 全按 Shift（敏感度） | 同上 | 一律按 Shift 直打 |
| 混輸開著 | 收得進 lattice 的英文詞和前後的中文一起連打到上屏 | 收不進的照規則 4 那一列 |

- 每次組字（從空的組字打起、打到上屏）是首選字基準的一題，用 `qim_bench::score_set` 模擬修正次數（同首選字基準：首選接得上就按空白，否則選接得上的最長候選、翻頁，卡住時 Esc 一個單位一個單位打；中文一字、英文一詞是一個單位），預設選項、空白的學習資料、不給前文。
- Shift 直打不算修正，按鍵是字母數加 2（切過去、切回來）。
- 報：修正次數（整句加總）、比兩個基準多少、每句按鍵、零修正的句（打完不用選字、翻頁）、打不出的句。

### 純中文集（判準）

- dev：`qim_bench::run_dev`（首選字基準各語料的 dev 切分與它的短輸入、有前文給與不給、打錯碼與觸控模擬、固定題），每個設定一個行程，和關著的逐集合比答錯數與修正次數（`chinese`、`report`）。
- test：`QIM_INLINE_ENGLISH=<設定> cargo xtask bench --check`，比 baseline，含翻盤清單與每鍵延遲。

## 怎麼重跑

先 `git checkout aec9741`（機制還在的 commit）、`cargo xtask data`，在 repo 根目錄：

```sh
B=scripts/experiments/inline-english/target/release/inline-english
cargo build --release --manifest-path scripts/experiments/inline-english/Cargo.toml
$B extract                                  # 寫 build/inline-english/{dev,test}.tsv
$B words dev                                # 英文詞依長度、詞典有沒有的個數（不看結果）
$B mixed dev 22,5,140 30,5,140              # 混輸句：兩個基準與各設定
$B chinese off; $B chinese 22,5,140         # 純中文集 dev，各寫 build/inline-english/chinese-<設定>.tsv
$B report 22,5,140                          # 比關著多幾題
QIM_INLINE_ENGLISH=22,5,140 cargo xtask bench --check   # test
```
