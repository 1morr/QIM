# remembered-prefix：記住的字串要打幾個字母才給（M3 票 15）

- 日期：2026-11-11；機器：Apple M6、macOS 27.0.1；Python 3（只用標準庫）；commit `c623f86` 的首選字基準題目。
- 問題：記住的 email 在中文組字裡打它開頭的字母時給候選（排第 2 位起）。字母太少時，平常打中文也常撞上，第 2 位的字被擠開（brief §4.7 擔心的「按 2 選某字」）；太多又不方便。
- 量法：`bench/corpus/`、`bench/colloquial/` 的四個集合共 6,638 題，每題的輸入碼當一次組字；另把每個字的開頭都當成組字的開頭（逐字打時的上限）。取 20 個香港常見的 email 開頭（姓氏、英文名、`info`、`admin`…），算組字的輸入碼以它的前 N 個字母開頭的比例。

```sh
python3 -I scripts/experiments/remembered-prefix/collide.py bench/corpus/*.tsv bench/colloquial/*.tsv
```

## 結果

題數 6,638，字的開頭 62,914。

| N | 每題平均 | 每個字的開頭平均 | 最常撞的開頭 |
| ---: | ---: | ---: | --- |
| 2 | 0.1913% | 0.1761% | john（0.5722%） |
| 3 | 0.0143% | 0.0093% | admin（0.0509%） |
| 4 | 0.0009% | 0.0008% | john（0.0048%） |
| 5 | 0.0000% | 0.0000% | cheung（0.0000%） |

## 結論

採用「長過一個字的最長碼」（速成 3 個字母），同英文候選的門檻（plan §2.4 規則 4）：2 個字母是單字的碼，約每 500 次組字撞一次；3 個字母降到約每 1 萬次一次，每多記一個 email 照比例增加。4 個字母再少一個數量級，但 3 個字母已夠少，多打一碼的成本較明顯。
