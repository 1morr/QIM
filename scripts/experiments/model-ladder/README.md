## 怎麼重跑

```sh
cargo xtask data                                    # repo 根目錄；要有長前文題（build/corpus/<名>/*-context-long.tsv）
ln -s <主 checkout>/bench/personal bench/personal   # worktree 裡要個人集時（docs/development.md〈個人集〉）
cd scripts/experiments/model-ladder
cargo run --release -- eval                         # dev 切分的基線，約 50 秒
cargo run --release -- eval --split test            # test 切分加個人集：只在設定定案後跑一次
cargo run --release -- export [--split test] [--n 9] [--include-personal]
cargo run --release -- eval --orders <結果.jsonl> --name <模型名>
cargo run --release -- compare ../../../build/model-ladder/dev/baseline ../../../build/model-ladder/dev/<模型名>
cargo run --release -- by-length [--split test] ../../../build/model-ladder/<切分>/baseline ../../../build/model-ladder/<切分>/<模型名> …
cargo run --release -- context-stats [--split test]
```

- `eval` 印 Markdown 表，逐題結果寫到 `build/model-ladder/<切分>/<模型名>/<集合>.tsv`（只有行號與數字，個人集也一樣）。
- `export` 把每題的重排要求寫成 `build/model-ladder/<切分>/requests/<集合>.jsonl`（下面〈給實驗票〉），不含答案。個人集要加 `--include-personal` 才匯出；它的內容只在本機、不送雲端，雲端實驗要跑個人集每次先問使用者（plan §5.2）。
- `compare` 比兩個逐題結果目錄裡同名的集合：首選、前 2 名、可動首選各報翻好／翻壞與 McNemar 精確檢定（雙尾）的 p 值。
- `by-length`（票 25）把幾個逐題結果目錄（各一個模型）依答案字數分成 1–4、5–8、9–14、15 字以上，各組列首選、前 2 名與題數；組是口語、維基、個人與口語長前文的三種前文長度（「有前文」兩組不分）。逐題結果檔的最後一欄是答案字數，票 25 前寫的檔沒有這欄，要重跑。
- `context-stats`（票 25）印長前文題與口語長前文題的前文長度：p50、到 50 字與到 200 字的比例。
- 票 08 的 `sync`（已刪，見上）另有兩個除錯用的環境變數 `SHOW`、`EXPLAIN`，要用時同樣 checkout `a6b4550`。

## 量法

### 集合

| 組 | 集合 | dev 切分 | test 切分 |
| --- | --- | --- | --- |
| 維基 | yue-wiki、zh-wiki | `build/corpus/<名>/dev.tsv`（各 2,000 句） | `bench/corpus/<名>.tsv` |
| 口語 | common-voice-yue、hkcancor | `build/corpus/<名>/dev.tsv` | `bench/colloquial/<名>.tsv` |
| 有前文 | 四個語料各 `·前文0`、`·前文50`、`·前文200` | `dev-context-long.tsv` | `test-context-long.tsv` |
| 口語長前文 | `hkcancor·對話·前文0`、`·前文50`、`·前文200`（票 25） | `build/corpus/hkcancor/dev-dialogue.tsv`（968 題） | `test-dialogue.tsv`（988 題） |
| 個人 | personal | 不切（下面〈調參與報數〉） | `bench/personal/rime-userdb.tsv` |

- 有前文：和基準的「有前文」集合同一批題，前文改用同一段裡前面最多 200 字（`cargo xtask data` 寫的長前文題，plan §5.2）。`·前文0` 不給前文（同基準的 `·前文·不給`），`·前文50`、`·前文200` 給最後 50、200 字。核心只看前文的最後一字（plan §2.3），所以基線的 50 與 200 一樣；給重排模型的前文才有差別。長前文有多長：維基段落常超過 50 字，口語多半只有一兩句（test 的長前文 p50 是 8–79 字，見下面〈限制〉）。
- 每題用新的 `Session` 與空白的 `UserModel`，同首選字基準。

### 指標

- 首選正確率、修正次數：照首選字基準算（`qim_bench::score_set`，和 `cargo xtask bench` 同一份程式），定義見 `docs/development.md`〈首選字基準〉。
- 前 2 名命中率（「最高到第 2 位」規則，ADR 0005）：打完整串輸入碼、不選字，重排模型回它排的文字；顯示的第 1 名是核心的首選（不動），第 2 名是模型排的第一個不是首選的文字（模型沒排就照核心的第 2 個）。答案在這兩個裡就算命中。
- 可動首選時：模型自己排的第一名是答案的比例。ADR 0005 不讓重排動首選，這欄只當參考（`docs/research/neural-rerank.md` §5 建議兩種接法都量）。
- **重排改變不了首選與修正次數**：首選不動；修正次數的模擬選第一頁任何一個都算一次，第一頁內怎麼排都一樣。所以停鍵層與雲端層只看前 2 名命中率，首選與修正次數是同步層（票 08）的指標。
- 召回：答案在候選列的前 k 個、在 lattice 的前 k 條路徑的比例。後者是重排模型看 k 條路徑時前 2 名命中率的上限。
- 依組合計：每組的集合加起來；「有前文」依語料（維基、口語）與前文長度各一列，另有兩者合計的一列：口語的長前文很短，合在一起時前文長度的差別幾乎都來自維基。結論以口語與個人為主，維基只防退步（spec）。

### 重排模型看什麼

`Reranker::rerank(&Query) -> Vec<String>`。`Query` 有集合名、行號、前文、輸入碼、候選列第一頁（最多 9 個，依核心的順序）與 lattice 的前 N 條路徑及路徑分（`qim_core::Session::paths`）。模型可以挑候選列裡沒有、路徑裡有的文字：候選列只放方案的 3 條多段路徑（`ranking.sentences`），口語 dev 上答案有 56.3% 在候選列，在前 9 條路徑卻有 67.2%。要在產品裡放進候選列，`apply_rerank` 得能插入不在候選列的路徑，這由階梯結論票（票 11）定。

### 調參與報數

- 各票調參（神經分的權重 λ、插值權重、提示寫法、N）只看 dev 切分：維基與口語的 `dev.tsv` 和 dev 的長前文題。四個語料都有 dev 切分（plan §4.3 的 90／5／5，依句子雜湊切，dev 的句子不在 train，也不在 test）。
- test 切分與個人集只在設定定案後跑一次報數，採用門檻（spec〈採用門檻〉）也只看那一次。`--split test` 會印提醒；每次真的跑 test 都記在該票的 Comments。
- 個人集不切：它是使用者自己打過的詞（Rime 的學習資料），切一半拿來調參就是對著使用者的答案調；題數也會少一半。所以個人集完全不參與調參，只在定案後報數。
- 訓練神經模型的語料同樣只用 train 切分，並照 `docs/research/neural-rerank.md` §5 剔除所有評估句（票 09）。

### 讀法

- 重排的上限：口語 test 的前 2 名命中率 49.1%，前 9 條路徑裡有答案的是 68.0%，重排模型最多補 19 點；候選列第一頁裡有答案的只有 55.3%，只在候選列裡挑最多補 6.2 點。
- 個人集的詞短（p50 2 字），基線已經 76.0% 首選、前 9 條路徑 97.0%，重排能補的不多，主要看它不退步。前 2 名比答案在前 2 條路徑（86.6%）低 1 點，合併前只差 0.1 點：候選列的第 2 位有時不是第 2 條路徑，推測是合併進來的 emoji 候選這類由排位規則放進的項目，沒有逐題查。
- 前文：核心只看最後一字，50 與 200 字對基線一樣（表上合成一列）。給前文比不給：口語多 1.5 點首選、1.3 點前 2 名；維基首選少 0.1 點、前 2 名多 0.5 點（同票 04 的結論：合計較好，zh-wiki 持平）。
- 成本（同步層，`eval` 最後一行與 `cargo xtask bench`）：
  - 字級 bigram 資料包 3,018,934 位元組（2.9 MB），解開 2.7 ms（5 次中位數，2.4–2.9）。
  - 常駐記憶體：Mac 上載入後 footprint +12.3 MB、heap 7.5 MB（M2 票 04，`docs/research/ios-feasibility.md`〈Mac 上的資料包記憶體〉）。

### 怎麼接進核心

（票 11b 起已刪，見〈內容〉；以下記票 08 當時的做法。）核心加了實驗用的 `Engine::with_segment_model`（plan §2.1，`crates/qim-core/src/segment_model.rs`）：lattice 每條邊與整串字詞的靜態機率改問外部模型，它拿到前面最多 2 段、這一段與現行打分的靜態機率；β、γ、`personal`、候選列照核心。沒掛上時打分完全不變（`tests/segment_model.rs`；`cargo xtask bench --check` 13 個集合沒有翻盤）。所以首選、修正次數與延遲都是核心真的 Viterbi 量的，不是另寫一份。

### 模型

都在 `src/sync.rs`（票 11b 刪掉，見〈內容〉），「高一階、退回現行打分」：留下的 n-gram 用 interpolated KN 的式子，沒留下的乘退回權重 α 接回低一階，所以沒有統計的地方和基線一樣。

| 規格 | 模型 | 低一階 |
| --- | --- | --- |
| `char3:<門檻>` | 字級 trigram（前兩字 → 字），句首記號也算一個字 | 現行的字級 bigram |
| `word2:<門檻>`、`word3:<bigram 門檻>:<trigram 門檻>` | 詞級 bigram／trigram（前一、兩段 → 段） | 現行打分（首字 bigram 乘詞內詞頻） |

| `mix:<λ>` | 維基、口語各訓練一份標準 KN bigram，線性內插 | — |

- 語料：`cargo xtask data` 寫的四份 train 切分，權重同字級 bigram（維基 1、口語 64，plan §4.3）。
- 詞級的段：用現行打分把訓練句切成段（文字已知的 Viterbi：詞庫的詞與單字，分數同 lattice 的邊，β、γ 照方案），和輸入法解碼時的切法一致；dev 上訓練語料切出 215,121 種段。
- 折扣：預設各語料在自己的原始次數上算 `D_k = n1 ÷ (n1 + 2 n2)`，一種 n-gram 扣 `Σ D_k × w_k`（等於各語料分開訓練再依權重把次數加起來，標準 KN 的做法）；規格結尾加 `:w` 用現行的做法（`D` 在乘權重後的次數上算，口語幾乎不扣）。
- 剪枝：只留乘上權重後次數 ≥ 門檻的（口語出現一次就是 64），重算 α 讓機率加總為 1；α 夾在 1 以下（下面〈除錯〉）。
- 大小：表（前文、gap 的 varint、`u8` 量化的 ln P、`f32` 的 α）與詞級的段表（文字）用 postcard 序列化的位元組數，同核心的語言模型資料包；預算比的是「這份加上字級 bigram 的 3.02 MB」。常駐是陣列長度乘元素大小加雜湊表的估計，不是量出的 footprint。解開是由位元組建出查表結構的時間（5 次中位數）。
- 延遲：`qim_bench::native_timing`，和 `cargo xtask bench` 同一份計時（固定題與四個語料 test 的每一鍵、選開頭一段），每個模型掛上後量一次；同一次執行另量不掛模型的 `bigram` 當對照。

### 除錯：α 爆大（dev 上發現）

第一次掃 `char3` 時，給前文反而比不給差（維基有前文 54.2% → 52.0%，基線兩者持平），首字常變成罕用字（「蘋在克里米亞…」）。查表：罕用字當前文時，低一階幾乎全給了留下的那一兩個後字，`1 − Σ 留下的 P_低` 近 0、又受 bigram 量化誤差左右，重算的 α 到 e^13 以上，沒留下的 trigram 反而比低一階高得多。α 夾在 1 以下後，給前文比不給好（51.2% → 51.9%）。下面的數字都是修正後的；修正前跑的 `char3:8`、`32`、`128`、`8:w` 不列。

### 讀法（對 spec〈採用門檻〉）

- 門檻的絕對值：口語首選 ≥ 38.3%、修正 ≤ 2.348；個人首選 ≥ 75.5%、前 2 名 ≥ 85.0%、修正 ≤ 0.3315；維基首選 ≥ 42.8%、前 2 名 ≥ 54.1%。成本：預算版資料包 ≤ 8 MB、每鍵 p95 ≤ 1 ms、選開頭一段 p95 ≤ 5 ms、載入 ≤ 300 ms。
- 預算版兩種都過：`char3:10` 口語首選 +6.0 點、修正 −10.7%；`word3:8:8` +8.2 點、−15.5%。同一層較貴的一級要比已採用的較便宜那級再過門檻：`word3:8:8` 比 `char3:10` 首選 +2.2 點、修正 −5.4%、p = 0.0004，也過。延遲在忙碌的機器上每鍵 p95 也只到 0.1 ms 級、選開頭一段 1.9 ms，離門檻一個數量級；載入（解開，不含讀檔；字級 bigram 的 2.7 ms 引〈基線結果〉）合計 9–14 ms。
- 放寬版要比預算版首選再多 2.0 點：`char3:2` 比 `char3:10` +2.1、`word3:2:4` 比 `word3:8:8` +2.2，都過，但都只多一點點。照「比已採用的較便宜那級再過門檻」，採用 `word3:8:8` 時 `char3:2`（44.4%）連它（44.5%）都沒贏，不過；`word3:2:4` 比 `char3:2` 也多 2.3 點（p = 0.0004）。常駐 35 MB 是估計，iOS 鍵盤擴充的峰值增量要在 iPhone 量（M2 票 09 的量法），票 11 決定要不要量。
- 不設預算的 `word3:1:1`：照「較貴的一級要比已採用的較便宜那級再過門檻」**不過**：比放寬版 `word3:2:4` 只多 1.6 點（要 2.0；修正 −4.5%，p = 2.2e-5）。只照它自己那條「口語首選比基線多 4.0 點以上才做」是過的（+12.0）。兩條的先後由票 11 定。解開 dev 306 ms、test 262 ms（不含讀 149 MB 的檔），常駐估計 316 MB，只能桌面、可選下載。
- 維基集的增益比口語大很多（`word3:1:1` +18 點）：維基有大量格式相近的句子（人物、地名條目），越不剪枝越像背下來；`qim-databuild` 的洩漏檢查只擋原樣出現的句子。結論以口語為主（spec），維基只防退步。
- KN（M1 票 24）：字級 bigram 改成各語料各算折扣（`kn2:2`）沒有好處：口語首選 −0.1 點、修正 +2.0%（p = 0.85），維基也略差；現行的「乘權重後算 D」對 bigram 撐得住（plan §4.3 的推測成立）。但高一階的模型要用各語料各算：同樣門檻，現行做法的 `char3:10:w` 口語首選比 `char3:10` 低 3.5 點、`word2:8:w` 比 `word2:8` 低 1.6 點（dev）。原因：口語的 n-gram 次數至少 64，現行做法幾乎不扣，口語前文的退回質量近 0，沒見過的接續被壓得很低；bigram 的前文多、接續密，影響小。`mix`（分開訓練、線性內插）在任何 λ 下不是口語差就是維基差：內插權重不看前文，次數相加等於依前文在兩個語料的次數加權，才分得出哪邊的統計可信。
- 「說」「記」（M1 票 17b）：test 的基線只剩 3 處（期望「記」首選「說」，反向 0 處，1,649 題），各模型 2–4 處，n-gram 沒有改善；兩字的前後文都常見，要看語意。M1 時的多錯已在之後的資料包改動中變少，不再是口語集的主要錯誤。

### 訓練資料與授權（brief §11）

- 四份語料的 train 切分，和字級 bigram 同一批：中文維基、粵語維基（CC BY-SA 4.0）、HKCanCor（CC BY 4.0）、Common Voice 粵語句子（CC0），見 `bench/*/ATTRIBUTION.md` 與 `data/sources.toml`。
- 詞級模型另用詞庫（rime-essay，LGPL-3.0）的詞與詞頻切訓練句，段表與 n-gram 都由它而來：詞級模型隨 App 發佈同時受 CC BY-SA 與 LGPL 的待決項影響（brief §11）。字級 trigram 只受 CC BY-SA 影響，同字級 bigram。

### 限制

- 常駐記憶體是陣列長度的估計，不是 footprint；詞級的段表用雜湊表查文字，產品會在建 lattice 時給段編號，延遲會再少一點。
- 延遲在忙碌的機器上量，只看倍數與門檻的距離；WebAssembly 沒量（實驗模型不在 `qim-wasm` 裡）。
- 組字開頭只接得到一段前文（選定的分段、剛上屏的那段，或前文的最後一字、句首，`Preceding`），所以 trigram 在組字開頭最多看前一字與句首；接前文的兩段要改 `Session` 記的前文。
- 並存寫法（brief §4.1）的另一種寫法在高一階的表裡沒有照抄，打到它時退回字級 bigram（評估的題目都寫代表寫法）。
- 聯想仍用字級 bigram（plan §2.3），沒有比。
- 詞級模型的段由現行打分切出；換了詞庫或 β、γ 要重訓。

## 限制

- 只在打完整串輸入碼時重排一次；實際上使用者可能在停鍵層回來前就按空白，青簡記下過這種競態（`docs/research/neural-rerank.md` §1.7）。
- 前 2 名命中率假設使用者等到結果才看候選列。
- 有前文的題都是整句，前文以標點結尾，核心接句首（plan §2.3）；長前文只多給重排模型看。
- 長前文多長取決於語料：test 的長前文 p50 是 common-voice-yue 8 字、hkcancor 16 字、yue-wiki 54 字、zh-wiki 79 字；到 50 字的比例 0%、17%、54%、66%，到 200 字的 0%、1%、6%、16%（dev 相近）。所以前文 200 字那檔實際上只在維基量得到，口語的 50 與 200 幾乎相同。HKCanCor 每句話是一行，票 25 把同一段對話接起來做了口語長前文題（前文 p50 200 字，〈依句長分組與口語長前文〉）。
- 神經模型延遲的重算是忙碌機器上的倍數推估，不是 iPhone 實測（上面〈N 與路徑長度〉）。
