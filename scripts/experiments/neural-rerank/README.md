# neural-rerank：停鍵層的小型神經重排（M3 票 09）

- 日期：2026-11-11；機器：Apple M6（Mac18,5，32 GB）、macOS 27.0.1（26A434）；iPhone 18 Pro Max（iPhone19,7）、iOS 27.2（24B119）。
- 版本：PyTorch 2.15.0（MPS）、Python 3.13.17、numpy 2.5.4、safetensors 0.8.0（釘在 `train.py.lock`，uv 0.13.5）；推論 candle-core、candle-nn 0.11.1（CPU，2 條執行緒）、rustc 1.99.1。
- commit：開工 `fa07bd3`；README 不寫含它自己的 commit（同 `../model-ladder/`），重跑用 `git log -- scripts/experiments/neural-rerank` 對。
- 問題（`.scratch/m3/spec.md`〈模型階梯實驗〉停鍵列）：自己訓練 Gboard 級（約 1.4M 參數）與青簡級（約 23M）兩個字級神經模型，重排 lattice 的前 9 條路徑，前 2 名命中率比基線好多少、成本是否在〈採用門檻〉內。

## 結論

- **1.4M（CIFG-LSTM）過了停鍵層的門檻**：test 口語前 2 名 49.05% → 57.54%（+8.5 點，翻好 268／翻壞 44，McNemar p ≈ 2×10⁻⁴⁰），個人集與維基沒退步；iPhone 上 q8 重排一次（9 條 × 18 字、上下文 200 字）p95 10.7 ms、峰值 +2.0 MB、檔案 1.62 MB。
- **23M（GPT 式 decoder）沒過**：口語 58.95%，只比 1.4M 多 1.4 點（門檻要再多 2.0 點；配對 98／61，p = 0.004）；iPhone 上 q8 p95 84 ms、峰值 +74–75 MB，延遲與記憶體也都超標。它在維基多得多（66.2% 對 60.0%），但維基只防退步。
- 前文：給 50 字比不給多 1.8（1.4M）、2.7 點（23M）；給 200 字比 50 字只差 ±0.1 點（有前文組）。口語的長前文本來就很少到 200 字（`../model-ladder/README.md`〈限制〉）。
- 讓模型動首選的話，個人集首選會從 76.0% 掉到 71.7%（1.4M）、73.3%（23M）：維持 ADR 0005 只動第 2 位。
- **上面的命中有一部分是候選列沒有的句子**：模型從 lattice 前 9 條路徑挑第 2 名，候選列第一頁只放 3 條整句，口語答案在第一頁的只有 55.34%。1.4M 的 1,518 題命中裡 163 題（6.2 點）是第一頁外的路徑；現在的 `apply_rerank` 只能在候選列內排，照現況接，口語前 2 名落在 51.4%～55.3%（〈結果〉的「只在第一頁內重排」），可能過不了 +4.0 點。要拿到 57.5% 得讓核心能把路徑插進候選列，由票 11 和採用一起定（票 10 也有同樣的發現）。
- 採不採用由票 11 定；這裡只報數字與門檻比較（下面〈與門檻比較〉）。

## 模型

結構與權重名照 `../neural-cost/src/model.rs`（M2 票 11 量開銷的那兩個），參數量也相同，所以 M2 與票 07 量的開銷直接適用，本票在 iPhone 用 9 條 × 18 字重量（〈成本〉）。

| | Gboard 級 `lstm` | 青簡級 `gpt` |
| --- | --- | --- |
| 結構 | 單層 CIFG-LSTM 670 單元，投影回 96 維，輸入輸出共用 embedding | GPT-2 式 decoder，pre-LayerNorm，寬 512、6 層、8 頭，上下文 256，學到的位置 embedding，共用 embedding |
| 字表 | 10,000（含兩個記號） | 8,000（含兩個記號） |
| 參數 | 1,412,250 | 23,142,400 |
| 檔案（1 MB = 1,048,576 位元組，同 neural-cost） | f32 5.39 MB、q8 1.62 MB | f32 88.29 MB、q8 23.57 MB |

- 字表：train 切分的字依次數排（口語乘 64，同 bigram 的語料權重，plan §4.3），取前 9,998／7,998 字，涵蓋 train 字次的 99.998%／99.991%；其餘是 `<unk>`，路徑裡每個 `<unk>` 另扣 `ln(字表外的字數)`，把 `<unk>` 的機率平分給字表外的字。
- `<sep>`：句首記號兼子句分隔。語料在標點、空白、符號處切句（plan §4.3），`train.txt` 一行一個子句、依原文順序；訓練時子句間插 `<sep>` 接回連續文字。前文裡的標點、空白、符號連續的收成一個 `<sep>`，英文、數字等字表外的字母數字收成一個 `<unk>`。
- GELU 用 tanh 近似（candle 的 `gelu()`）。PyTorch 與 candle 的分數用 `reference.json`（訓練完寫的 4 組前文 + 路徑）核對，`model-ladder neural` 讀到就比：f32 差 ≤ 0.0001 nat。

## 語料與訓練

- 語料：`cargo xtask data` 的 train 切分（plan §4.3 的 90／5／5，依句子雜湊切），四個語料：

  | 語料 | 子句 | token（含 `<sep>`） |
  | --- | ---: | ---: |
  | zh-wiki | 4,999,496 | 51,313,555 |
  | yue-wiki | 2,159,865 | 20,846,903 |
  | common-voice-yue | 31,310 | 292,203 |
  | hkcancor | 24,478 | 164,035 |

- 剔除評估句（`docs/research/neural-rerank.md` §5）：基準、dev 調參題、長前文題與個人集的答案句，5 字以上的整句從 train 拿掉；train 本來就不含 dev、test 的句子，結果只拿掉 3 句（個人集的詞）。長前文題的前文是同一段前面的句子，可能在 train 裡；答案句不在。
- 取樣：每個視窗從一個子句開頭（`<sep>`）起、257 個 token，依比例從四個語料抽：維基兩個照大小分 `1 − f`，口語兩個照大小分 `f`。口語只有約 46 萬 token，`f` 是調得最多的參數（〈調參〉）。
- 硬體：同一台 Mac 的 GPU（MPS）；量的時候別的 session 也在用 CPU 與 GPU，訓練時間只當量級。

定案的兩個模型（調參過程見〈調參〉）：

| | 1.4M `lstm-c0.5` | 23M `gpt-c0.15` 第 4000 步 |
| --- | --- | --- |
| 口語視窗比例 `f` | 0.5 | 0.15 |
| 步數 × batch × 256 | 4,000 × 128（1.31 億 token，約 1.8 輪） | 4,000 × 64（6,550 萬 token，約 0.9 輪；跑到 5,000 步，挑第 4000 步的檢查點） |
| 口語 token 看過幾遍 | 約 140 | 約 21 |
| 最佳化 | AdamW（β 0.9、0.95），lr 2e-3，warmup 200，cosine 降到 10%，weight decay 0.01（只矩陣），梯度裁到 1 | 同左，lr 6e-4，weight decay 0.1，dropout 0.1，bf16 autocast |
| 時間 | 49 分鐘（和 GPT 同時跑；單獨跑同設定約 18 分鐘） | 74 分鐘跑完 5,000 步（同時有 LSTM 在跑） |
| dev 損失（nat/字：zh-wiki、yue-wiki、common-voice-yue、hkcancor） | 5.40、5.17、4.63、4.17 | 3.84、3.92、3.87、3.85 |

dev 損失只取各語料 dev 切分開頭 20 萬 token、不重疊的 256 字視窗；dev 的句子在原文裡不相鄰（中間隔著 train、test 的句子），所以比 train 的損失高。

## 接法

- 一題：核心打完整串輸入碼後的前 9 條 lattice 路徑（`Session::paths`，票 07 的 N）與前文（集合給的 0、50、200 字）。
- 神經分：路徑各字 log 機率的和（nat），前文只算一次、狀態給 9 條路徑共用（前綴快取，`../neural-cost/README.md`〈前綴快取〉），路徑補齊成一樣長一批算、補的位置遮掉。GPT 的前文截到「句首 + 前文 + 最長路徑 − 1 ≤ 256」。
- 排名：`路徑分 + λ·神經分` 由高到低，`λ = inf` 是只看神經分（同分看路徑分）。路徑分是核心的同步層分數（字級 bigram 與詞庫，也是 nat）。神經分只決定名次、不寫回分數（plan §2.7）。研究筆記建議的 `λ·(神經分 − 靜態二元分)` 要拆出路徑分裡的 bigram 項，`Session::paths` 沒給，沒做。
- 顯示：首選不動（ADR 0005），第 2 名是排出的第一個不是首選的文字（`../model-ladder/` 的「最高到第 2 位」）。「可動首選」欄是假如讓它動首選、排第一的就是答案的比例，只當參考。

| GPT，`f` 0.15，第 2000／3000／4000／4500／5000 步 | 1 | 59.0／59.7／**60.1**／60.0／60.0% | 62.8／63.9／64.3／64.7／64.7% | 60.9／61.5／61.0／—／—% | 66.1／67.0／67.5／—／—% |

- `f`：LSTM 口語比例越高口語越好、維基越差；0.5 比 0.3 口語多 0.8 點，但訓練不穩（第 1000 步維基損失跳到 7.9）、第 2500 步後口語損失回升。訓練更久沒有幫助（8,000 步那列），1.4M 的容量是瓶頸。
- GPT 先試過 `f` 0.3（沒有 dropout 以外的處理）：口語 dev 損失第 1500 步後一路回升（第 3000 步 4.63、4.67，第 1000 步 4.27、3.91），維基還在降，是過擬合口語（口語 token 每 1,000 步看約 11 遍），第 3000 步後停掉；改成 0.15 並每 500 步存檢查點，用 dev 的前 2 名挑。
- λ：0.25、0.5、1、2、inf 都掃過（`f` 0.1 的 LSTM），λ 1 與 2 最好、inf（只看神經分）口語少 0.4 點、維基少 1 點以上；之後各模型掃 0.5、1、2。定案時兩個模型都是 λ 1：LSTM 的 λ 0.5 與 1 口語同為 1,564／2,680 題，用有前文·口語（也是口語）較好的 1；GPT 第 4000 步的 λ 1（1,611 題）比 λ 2（1,610）多一題。這些差在雜訊內，照「dev 口語最多」的規則挑。
- q8 在 dev 和 f32 幾乎一樣（口語 LSTM 1,567 對 1,564、GPT 1,611 對 1,611 題）；test 兩種都報，門檻看要隨 App 發的 q8。

## 成本

### iPhone（門檻看這份）

模型檔大小見〈模型〉；q8 與 neural-cost 的隨機權重檔位元組數相同。

## 怎麼重跑

```sh
cargo xtask data                                  # repo 根目錄；語料的 train、dev 切分與長前文題
ln -s <主 checkout>/bench/personal bench/personal # worktree 裡要個人集時（docs/development.md〈個人集〉）
cd scripts/neural-rerank                          # 票 11d 起訓練程式在這裡
uv run --script train.py prepare                  # 字表與 token 檔，約 15 秒
uv run --script train.py train --model lstm --name lstm-c0.5 --steps 4000 --batch 128 --lr 2e-3 --weight-decay 0.01 --colloquial-frac 0.5
uv run --script train.py train --model gpt --name gpt-c0.15 --steps 5000 --batch 64 --lr 6e-4 --dropout 0.1 --colloquial-frac 0.15 --save-checkpoints   # 用 step4000/
# 調參的其他幾次：--colloquial-frac -1（自然比例）、0.1、0.3；LSTM 0.3 加 --steps 8000 --eval-every 1000 --save-checkpoints
cd ../experiments/model-ladder
cargo build --release
B=../../../build/neural-rerank
./target/release/model-ladder neural --model $B/<名>/model.safetensors --vocab $B/data/vocab.txt --lambdas 0.5,1,2   # dev 掃 λ
./target/release/model-ladder quantize $B/<名>/model.safetensors $B/<名>/model.gguf
./target/release/model-ladder eval --split test                                       # 基線
./target/release/model-ladder neural --split test --model <定案的檔> --vocab $B/data/vocab.txt --lambdas <定案的 λ> --name <名>
./target/release/model-ladder compare ../../../build/model-ladder/test/baseline ../../../build/model-ladder/test/<名>-λ<λ>
```

iPhone 的成本：照 `../ios-keyboard/README.md`〈小型神經模型（票 11）〉建置、安裝，在備忘錄叫出實驗鍵盤，按 `G8·9`、`L8·9`（每個模型一個新程序）。

## 限制

- 一次訓練、一個種子：`f`、步數、λ 的差多半在 1 點內，沒有重複訓練量變異；23M 對 1.4M 的 +1.4 點也是一次訓練的結果。
- 訓練時 GPU 與 CPU 和別的 session 共用，時間只當量級；Mac 的延遲同樣受干擾。
- 停鍵層只在打完整串時重排一次，假設使用者等到結果才看候選列；「停鍵後立刻按空白」的競態（`docs/research/neural-rerank.md` §5）要等產品接入時量。
- 只重排 lattice 前 9 條路徑；候選列只放 3 條，把路徑放進候選列要 `apply_rerank` 能插入（票 07，由票 11 定）。
- 沒照研究筆記做 `λ·(神經分 − 靜態二元分)` 與位置先驗：`Session::paths` 只給合計的路徑分。
- iPhone 的成本是隨機權重、固定 9 × 18 字的探針（值不影響開銷）；只量了旗艦機，低階機在 M7。
- 口語的長前文沒有接：HKCanCor 一句話一行，要量口語的長前文得把同一段對話接起來（`../model-ladder/README.md`〈限制〉）。本票沒接：門檻看的是不給前文的口語組，有前文組的 50 與 200 字在口語幾乎相同；要不要接留給票 10、11。
- 洩漏防線只做了剔除評估句（`docs/research/neural-rerank.md` §5 的三條之一）：語料本來就依句子雜湊切 train／dev／test，評估句不在 train；「按對話留出」要重切語料、會改基準的題，「公平子集」是給訓練資料不同的模型比較用的，這裡兩個模型用同一份 train。test 長前文題的前文在 train 裡（〈語料與訓練〉）。
- 口語語料只有約 5.6 萬句（使用者 2026-11-11 決定先用現有語料，plan §8）：1.4M 的口語比例調到 0.5 才停止進步、23M 在 0.3 就過擬合，語料多一些可能改變 23M 對 1.4M 的結論。
- 訓練出來的模型受語料授權影響（維基 CC BY-SA 4.0），同 bigram 列在 brief §11 的待決項。
