- **R1** rime-quick 的 quick5 匯入倉頡全碼表 `cangjie5.base`，用 `derive/^([^z])\w+(\w)$/$1$2/` 另加速成碼；`derive` 保留原拼寫且不降權，所以倉頡全碼也是合法輸入、排序時與速成碼不分。`rime-quick` `5dcdb9e`；`src/rime/algo/calculus.h:72-73`。
- **R2** script_translator 只要有詞條精確覆蓋整段輸入就不造句。`src/rime/gear/script_translator.cc:502-505`。
- **R3** 同長度候選先比是否精確匹配、再比剩餘碼長、最後比詞頻。`src/rime/dict/dictionary.cc:73-84`。
- **R4** 不用語言模型造句時每多一個詞扣 log(1e-6)。`src/rime/gear/grammar.h:18-27`。
- **R5** 使用者詞熱度隨上屏次數指數衰減，時間常數 200 次。`src/rime/algo/dynamics.h`、`src/rime/dict/user_dictionary.cc:425-457`。

- **R13** punctuator 的 `digit_separators`（預設 `.:`；2025-01 `28a234f0` 加入時是 `,.:'`，2025-11 `fd69bd70` 縮成 `.:`，commit 只有標題「update default digit separators」、沒有關聯的 PR）：沒有組字、上一筆上屏紀錄是直接打出的（`thru`、`raw`）且以半形數字結尾時，分隔符成為帶 `punct_number` 的待定分段，唯一的候選是它自己；接著按數字或空白，連同分隔符上屏；再按同一個鍵改回該鍵原本的標點（double strike）；其他鍵照一般組字，分隔符保持半形。`digit_separator_action: commit`（`4b90ff10`）改成立刻上屏，就沒有 double strike：上屏紀錄是 `punct` 的分隔符，下一個同樣的鍵已不算在數字後，照一般標點。上屏紀錄裡，沒處理的鍵中可見 ASCII 記成 `thru`，BackSpace、Return 清空紀錄，其他鍵不記。2025 年以前的 punctuator 只在 `ch == '.' || ch == ':'` 時讓數字後的鍵交給宿主，[issue #972](https://github.com/rime/librime/issues/972)（2025-01-12，主張數字後的標點不要自動轉半形，`digit_separators` 隨後加入）引用了這段舊程式碼。librime `9777cb2`：`src/rime/gear/punctuator.h:38-39`、`src/rime/gear/punctuator.cc:79-92,105-112,139-176,327-334`、`src/rime/commit_history.cc:20-31`，2026-11-05 查。
- **R14** ascii_composer（中英切換）：單按修飾鍵是按下後 500 ms 內放開、中間沒有別的鍵（任何一般鍵按下或放開都解除：「other keys」分支不分按下放開，所以按住 a 時按下 Shift、先放開 a 再放開 Shift 不切換）。組字中切換的處理由 `switch_key` 選：`inline_ascii`（留著組字接英文）、`commit_text`（`Context::ConfirmCurrentSelection`：只把最後一段標成選定、確認它選的候選，接著切 `ascii_mode`，沒確認的碼在英文模式下變原樣）、`commit_code`（上屏原碼）、`clear`、`noop`；rime-prelude `default.yaml` 的預設是 `Shift_L: inline_ascii`、`Shift_R: commit_text`。[`ascii_composer.cc`](https://github.com/rime/librime/blob/master/src/rime/gear/ascii_composer.cc)、[`default.yaml`](https://github.com/rime/rime-prelude/blob/master/default.yaml)，2026-11-04 查 master；other keys 與 `commit_text` 另對 1.17.0：`src/rime/gear/ascii_composer.cc:60-122,257-258`、`src/rime/context.cc:168-182`，2026-11-05 查。
- **R15** 未發佈的 master 的 ascii_composer（`74bd5dc4` 起，QIM 不照它，見下一條與 §4.3）的 `inline_ascii`（臨時西文）：進入時記下輸入與按鍵、抹掉沒確認的組字，輸入換成按下的鍵原樣，開 `ascii_mode`。臨時西文中 0x20–0x7e 的字元都推進輸入；空白上屏「輸入＋空格」、Return 上屏輸入，都清空並關 `ascii_mode`。再按 `inline_ascii` 的鍵切回：按鍵和進入時相同、且之間沒按過退格（退格會丟掉進來前的輸入）就還原原本的輸入，否則上屏目前的英文；`commit_text` 是確認目前的選擇（臨時西文中即上屏英文）。組字清空（退格刪光、Esc）時也回中文。左右 Shift 一起按：第二個按下時不重新計時，放開任一個就用那個鍵切換並解除。librime `9777cb2`：`src/rime/gear/ascii_composer.cc:99-113,124-176,212-221,247-268,411-479,481-494`；rime-prelude `082425e`：`default.yaml:66-70`，2026-11-05 查。
- **R16** 目前發佈版的 ascii_composer（≤ 1.17.0；librime `74bd5dc4`（2026-09-15，`feat(ascii_composer): commit_raw_input`）在 master 改寫，還沒進任何正式版，1.16.0 到 1.17.0 `33e78140` 這段沒變）：`ascii_mode` 且組字中時鍵碼 0x20–0x7f（`ch >= 0x20 && ch < 0x80`，含空白）一律推進輸入，其餘鍵交給後面的 processor；`inline_ascii` 進入時不動組字，只開 `ascii_mode`、由 ascii_segmentor 把沒確認的輸入標成原樣；組字清空時關 `ascii_mode`。實測（鼠鬚管內建 librime 1.16.0、quick5）：`anr`、左 Shift、`hello`、空白、`world`、Enter 上屏 `anrhello world` 並回中文；Enter 是 express_editor 的上屏原碼；退格逐字刪、刪光回中文；Esc 清空回中文；右 Shift（`commit_text`）上屏英文回中文；再按左 Shift 一律把目前整串當中文的輸入碼重新組字（`anrx` 回到中文組字，空白當分隔），不看打過字或退格過；已選定的分段留著；← / Home 移游標、Delete 刪游標後的字，Tab、PageDown、↑ ↓ 無作用。librime `74bd5dc4^`：`src/rime/gear/ascii_composer.cc:120-141,243-277`；復現：`scripts/experiments/rime-inline-ascii/`，2026-11-05 查。最新正式版是 1.17.0（2026-06-06），`latest` 是 master 的 rolling prerelease（2026-11-04 更新），[librime releases](https://github.com/rime/librime/releases)，2026-11-05 查。
- **R17** 分隔符（`speller/delimiter`，luna_pinyin 是 `" '"`）：speller 收方案字母與分隔符的鍵，分隔符照樣推進輸入（`xi'an` 就是輸入）；音節切分把緊接的分隔符算進前一個音節，所以 `xi'an` 不會切成一個音節 `xian`，但詞可以跨過分隔符（`xi'an` 仍出「西安」），沒找到禁止詞跨過它的程式碼；含分隔符的候選不自動選定。組字顯示的是含分隔符的那段輸入。使用者詞典的碼由音節組成（每個音節接一個空白），不含使用者打的分隔符。librime `9777cb2`：`src/rime/gear/speller.cc:46-55,75,109,129`、`src/rime/algo/syllabifier.cc:58-62,115-118`、`src/rime/gear/script_translator.cc:417-439`、`src/rime/dict/user_dictionary.cc:790-799,963-981`；rime-luna-pinyin `56b934b` `luna_pinyin.schema.yaml:70`，2026-11-05 查。
- **R18** 速成與倉頡的分隔符不一樣：速成 quick5 用 `script_translator`、分隔符 `" ;'"`，speller 的 algebra 把每個字的倉頡碼取首尾兩碼當一個音節，詞表是 `use_preset_vocabulary` 的詞（由字的碼組成），所以同上一條，詞可以跨過落在字界上的分隔符；組字顯示把 `;`、`'` 換成「·」。倉頡 cangjie5 用 `table_translator`、分隔符 `" ;"`（沒有 `'`）：查碼時去掉結尾的分隔符，從每個起點對整串輸入做前綴查詢，分隔符只在一個碼查到之後才吃掉，所以詞不跨分隔符。rime-quick `5dcdb9e`：`quick5.schema.yaml:47,55-57,62-63`、`quick5.dict.yaml:7-10`；rime-cangjie `fcb3d7d`：`cangjie5.schema.yaml:50,58`；librime `9777cb2`：`src/rime/gear/table_translator.cc:258,521-527,637-650`，2026-11-05 查。
- **R19** librime 不讀宿主的游標前後文（沒有這個 API）：組字從頭開始時，`contextual_suggestions` 開著的翻譯器把 commit history 的最後一筆當前文（`GetPrecedingText`：`start > 0` 取組字內前段，否則 `commit_history().latest_text()`）。commit history 最多 20 筆，記上屏的字與沒處理的可見 ASCII 鍵（`thru`），退格與 Enter 清空；沒找到換輸入框時清空的程式碼。數字後半形也只看它（`is_after_number`：最後一筆是 `thru` 或 `raw` 且以數字結尾）。librime `c95c0d2`：`src/rime/gear/script_translator.cc:325-329`、`src/rime/commit_history.cc:14-26`、`src/rime/gear/punctuator.cc:78-86`，2026-11-11 查。
- **R20** 退格撤銷（librime `Memory`）：每次上屏 `OnCommit` 先 `StartSession`，使用者詞典的 `NewTransaction` 先 commit 上一筆還沒 commit 的交易、記下開始的時間（`time(NULL)`），再開新交易，這次上屏的 `UpdateEntry` 都寫在裡面。沒有 processor 吃下的鍵（`unhandled_key_notifier`）到 `OnUnhandledKey`：Shift 以外的修飾鍵都沒按時，BackSpace 且交易開始不到 3 秒就 `DiscardSession`（`RevertRecentTransaction`：資料庫 abort、清掉 pending、重讀 `/tick`，所以連 tick 一起回滾），其他鍵 `FinishSession`（commit）；按著 Ctrl、Alt 這類修飾鍵的鍵兩者都不做。被 processor 吃下的鍵（組字中的鍵、librime-predict 收起聯想的退格）不到這裡，所以打了字又刪光再按退格，仍會撤銷 3 秒內的上一次上屏。librime `bb56876`：`src/rime/gear/memory.cc:99-109,128-160`、`src/rime/dict/user_dictionary.cc:923-947`、`src/rime/engine.cc:185-194`，2026-11-12 查。QIM 的取捨見 plan §2.4〈退格撤銷〉。
- **R21** 刪候選（撤銷學習）：editor 的預設綁定是 `Control+Delete` → `DeleteCandidate`，作用在目前高亮的候選（`Context::DeleteCurrentSelection`，高亮預設是第一個）；`Shift+Delete` 也生效，是 `KeyBindingProcessor` 的 `ShiftAsControl` 退路把 Shift 當 Ctrl，librime 沒有直接綁它。效果是 `Memory::OnDeleteEntry` 對使用者詞典 `UpdateEntry(entry, -1)`（`c` 取負，§12.2 上面「`c` 為負代表已刪除」），只對使用者詞典裡的詞有效，再次上屏就復活，不是永久屏蔽。鍵盤沒有「刪第 N 個」的路徑：`Context::DeleteCandidate(index)` 只經 C API 傳序號，`key_binder` 的 `select` 只選不刪。librime `bb56876`：`src/rime/gear/editor.cc`（約 198–214 行）、`src/rime/context.cc`、`src/rime/gear/memory.cc`，2026-11-12 查（M4 票 16）。
