# 事實：成熟產品的做法

查證過的外部事實，一條一個編號（`M` 加流水號），編號不重用，別處用編號引用。索引在 [brief〈事實索引〉](../design-brief.md)。

## 事實


- **M1** Gboard 解碼：lexicon FST、n-gram LM、空間模型組合後 beam search；按鍵約 20 ms 內回饋，鍵盤 LM 不超過 5–10 MB；個人化用動態模型加 on-the-fly lattice rescoring。[arXiv:1704.03987](https://arxiv.org/abs/1704.03987)。
- **M2** Gboard 下一詞預測：CIFG-LSTM 1.4M 參數、量化後 1.4 MB、詞表 1 萬；英文靜態 LM 為 Katz 5-gram 125 萬條。[arXiv:1811.03604](https://arxiv.org/abs/1811.03604)。
- **M3** Gboard 的神經 LM 皆以聯邦學習加差分隱私訓練；OOV 學詞取的是全體使用者的高頻詞。[arXiv:2305.18465](https://arxiv.org/abs/2305.18465)、[Google Research blog](https://research.google/blog/advances-in-private-training-for-production-on-device-language-models/)。
- **M4** macOS 27.0.1 與 iOS 27.0.1 的內建速成（黑箱實測）：都不做整串解碼，macOS 第 3 碼起整串改當英文、iOS 固定 2 碼一段且前段自動取首選；學習都是選一次就到第 1、只記最近一次，不學新詞；iOS 字序以粵語為主、繁簡混排，聯想看前文且離線時結果相同；macOS 組字中 Enter 上屏首選。[`docs/research/blackbox-baseline.md`](research/blackbox-baseline.md)，2026-11-04 測。
- **M5** Gboard 17.2.2 的速成（Android 17 模擬器，黑箱實測）：整串解碼（`mir` 一台），選開頭一段後其餘重算；容錯只靠點擊位置，原樣讀法優先，漏碼與對調不救；選 10 次不前移、不學新詞；字序粵語為主、繁簡混排；打碼的候選微受游標前文影響；沒有英文候選；組字中 Enter 上屏首選；字根鍵長按出英文字母。英文鍵盤打 3 次 email 後有時學會（觸發不穩，兩輪學到、一輪沒有），不是 autofill，模擬器重開後消失。iPhone 版有沒有速成未確認。[`docs/research/blackbox-baseline.md`](research/blackbox-baseline.md)，2026-11-04 測。
- **M6** fcitx 的表格輸入法：萬用鍵是每個碼表設定檔的一項（`UseMatchingKey` 開關、`MatchingKey` 指定哪個鍵），不是全域設定；QIM 照它放在方案檔（`wildcard`）。[fcitx wiki：How to make your own table-based input method](https://fcitx-im.org/wiki/How_to_make_your_own_table-based_input_method)（2026-11-12 查）。
- **M7** 刪指定候選的按鍵（M4 票 16，2026-11-12 查）：沒有跨產品的官方慣例。fcitx5 的拼音與表格（含速成、倉頡）是唯一能指定位置的：`Ctrl+7`（設定項 `ForgetWord`）進入「選要刪的詞」模式，再按數字鍵或點選，從使用者詞典移除並刪掉歷史（fcitx5-chinese-addons `e8d930f`：`im/pinyin/pinyin.h`、`pinyin.cpp` 的 `handleForgetCandidate`，`im/table/engine.h`、`state.cpp` 的 `handleForgetWord`）；`Ctrl+7` 在瀏覽器是切到第 7 個分頁，網頁攔不住。微軟拼音、注音、速成、倉頡的官方快捷鍵頁沒有刪候選的鍵（support.microsoft.com 的〈Microsoft Simplified Chinese IME〉〈Microsoft Traditional Chinese IME〉兩頁，簡中頁只有 Esc 與數字選字）；macOS 內建中文的 `Shift-Delete` 是復原文字替換，不是刪候選（Apple 中文輸入法快捷鍵頁）；搜狗只查到二手線索（滑鼠點候選的選單有「移除此詞」）。Rime 見 §12.2。
- **M8** 速成萬用鍵的語意（自測，`docs/research/wildcard.md`，2026-11-12）：每個 `z` 代一碼、任一位置，單獨一個代一碼字；比「單獨的 `z` 不算字」在一碼字的題多對約 4–6 點、沒有打不出，首碼、尾碼的題相同。整句忘一碼仍有原樣約七成的首選，單字首選 1–2%。
- **M9** 速成的容錯（自測，`docs/research/tolerance.md`，2026-11-13，M4 票 09）：照 §4.8 只修詞的邊、每條邊一處，懲罰在 dev 挑、test 跑一次。口語打錯的句子，四種修正（鄰鍵替換、多碼、漏碼、兩碼對調）全開時首選從 0.2% 到 9.7%（觸控 0% → 8.8%），但修正次數只少 3.9%／5.8%，原樣正確卻被改錯 1.8%／2.6%，沒打錯的集合答錯多 0.6–1.4%、修正多 2–6%；每鍵 p95 慢 16–18 倍、選開頭一段 32–48 ms。錯碼全改回來也只有約兩成落在「詞的邊、每段一處」。沒過門檻，不做。
- **M10** macOS 倉頡 / 速成可輸入英文字後從候選窗選，並有「Adjust word frequency」設定。[Apple 倉頡](https://support.apple.com/guide/chinese-input-method/cangjie-traditional-cimcjt11820/mac)、[Apple 設定](https://support.apple.com/guide/chinese-input-method/change-chinese-and-cantonese-settings-cim21aa5fa50/mac)。
- **M11** DeepSeek API 相容 OpenAI 與 Anthropic 的介面格式，模型為 `deepseek-flash` 與 `deepseek-v4-pro`；思考模式預設開啟，可用 `thinking` 參數關閉；Responses API 為無狀態、不在伺服器保存對話。[DeepSeek API Docs](https://api-docs.deepseek.com)、[Responses API](https://api-docs.deepseek.com/api/create-response)，2026-10-30 查。
- **M12** DeepSeek 2026-11-11 的模型與價格：`deepseek-flash` 是 DeepSeek-V4.1-Flash-1017，`deepseek-v4-pro` 是 DeepSeek-V4-Pro-0813（2026-09-14 後繼續提供、計費不變）；舊名 `deepseek-v4-flash` 暫時轉給 V4.1-Flash。每百萬 token 高峰價（北京時間平日 9–12、14–18 時）flash 輸入命中快取 0.04 元、未命中 2 元、輸出 8 元，v4-pro 0.30、9、27 元，其他時段半價。OpenAI 相容的 `POST https://api.deepseek.com/chat/completions` 以 `"thinking": {"type": "disabled"}` 關思考；只限並行數（flash 2500、v4-pro 500），沒有每分鐘上限；快取自動、盡力而為，`usage` 分列 `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`。[Models & Pricing](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)、[Change Log](https://api-docs.deepseek.com/updates)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)、[Rate Limit](https://api-docs.deepseek.com/quick_start/rate_limit)、[KV Cache](https://api-docs.deepseek.com/guides/kv_cache)，2026-11-11 查。
- **M13** DeepSeek `deepseek-flash`（關思考）做候選重排，提示約 280 字、只回一個序號：從這台 Mac 送，p50 742 ms、p95 1,083 ms，15,713 次沒有出錯、沒有超過 3 s；每千次 0.43 元（高峰價），快取命中只有輸入的 2.5%。[`scripts/experiments/llm-rerank/README.md`](../scripts/experiments/llm-rerank/README.md)，2026-11-11。
- **M14** Apple 端上基礎模型約 3B 參數；iPhone 15 Pro 每個 prompt token 約 0.6 ms、生成 30 token/s。[Apple ML Research](https://machinelearning.apple.com/research/introducing-apple-foundation-models)。
- **M15** llama.cpp 在 iPhone 15 Pro 的 Q4_0 實測：TinyLlama 1.1B prompt 646 token/s、生成 57 token/s。[llama.cpp #4508](https://github.com/ggml-org/llama.cpp/discussions/4508)。
- **M16** libime：KenLM trie，beam 20；每按一鍵增量更新 lattice 的只有拼音引擎（重用舊的位置、只算改過的），碼表引擎每鍵整個重算；拼音選定開頭一段後清掉 lattice、其餘從頭建。`53df6a2`，[`docs/research/libime-lattice.md`](research/libime-lattice.md)，2026-11-04 查。使用者歷史 bigram 以三個 LRU 池（128 / 8192 / 65536 句）固定權重混入。`fcitx/libime` `src/libime/core/decoder.h`、`historybigram.cpp`。
- **M17** libime 的使用者分數：`max(靜態, log10((1−w)·10^靜態 + w·10^歷史))`，`w = 0.2`，歷史只加分不扣分；歷史機率 = 0.2 × unigram + 0.8 × bigram，unigram 除以滿載歷史的總質量（三池權重合計 1.0），不是已學的句數；計數綁輸入碼的變體（`WordWithCode`）給碼表引擎用。授權 LGPL-2.1-or-later。`53df6a2` `src/libime/core/userlanguagemodel.cpp:122-140`、`historybigram.cpp:578-590,660-688`，[`docs/research/libime-user-model.md`](research/libime-user-model.md)，2026-11-04 查。
- **M18** Microsoft 繁體中文輸入法（注音、倉頡、速成）的候選窗：↓ 進入候選窗、在窗內往下移，Tab 或 → 展開成表格，Space 翻頁，數字鍵選字。[Microsoft Traditional Chinese IME](https://support.microsoft.com/en-us/windows/microsoft-traditional-chinese-ime-ef596ca5-aff7-4272-b34b-0ac7c2631a38)，2026-11-04 查。Apple 的候選窗說明沒寫展開的按鍵，只有方向鍵移動、`=` `-` 與 `[` `]` 換列。[Apple](https://support.apple.com/guide/chinese-input-method/use-the-candidate-window-cim12992/mac)。
- **M19** libime table 引擎的使用者詞庫文字檔沒有檔頭與版本號：手動詞一列 `code value`，自動造詞在 `[Auto]` 段多一欄次數 `code value hit`，被刪的系統詞在 `[Delete]` 段；以空白分隔，含空白的值加雙引號。`53df6a2`：`src/libime/table/tablebaseddictionary.cpp:946-998,1027-1051`，[`docs/research/userdict-text-formats.md`](research/userdict-text-formats.md) §2。
- **M20** 詞表的交換格式：Rime 碼表 `.dict.yaml` 前半是 YAML 檔頭、以 `...` 結束，之後是 Tab 分隔的列，欄位依 `columns:`（`text`、`code`、`weight`、`stem`），沒寫時預設 text、code、weight。Gboard 個人字典匯出成 zip，裡面的 `dictionary.txt` 第一行是 `# Gboard Dictionary version:1`（也見過 `# Gboard Dictionary format:shortcut…`），每列「快捷鍵<Tab>詞<Tab>語言」，快捷鍵可空。[RimeWithSchemata](https://docs.nopdan.com/rime/RimeWithSchemata.html)、[Rime Schema.yaml 詳解](https://hantang.github.io/rime-docs/collect/RimeDescription-Schema)、[Android Enthusiasts #195325](https://android.stackexchange.com/questions/195325/bulk-word-import-into-gboard)、[NatoBoram/PersonalDictionary](https://github.com/NatoBoram/PersonalDictionary)，2026-11-11 查（Gboard 沒有官方格式文件，取使用者匯出檔的樣本）。
- **M21** fcitx5-chinese-addons 的拼音預測不讀宿主文字，用這次組字選過的詞；標點模組的「英文、數字後用半形」平時靠自己記的狀態（上屏與沒處理的字母、數字鍵），宿主有 `SurroundingText` 能力且有效時，在聚焦或重設後的第一次更新用游標前一字校正。AOSP LatinIME 自己快取游標前的文字，宿主 `getTextBeforeCursor` 回 null 時退回空前文，不用自己的歷史猜。fcitx5-chinese-addons `e8d930f`：`modules/punctuation/punctuation.cpp:217-247`；LatinIME `127336e`：`RichInputConnection.java`（`reloadTextCache`），2026-11-11 查。
- **M22** rime-emoji 用 librime 的 `simplifier` 濾鏡（`simplifier@emoji`，`option_name: emoji_suggestion`，開關 `reset: 1` 預設開）：OpenCC 詞典的值是「原詞 emoji…」（`笑	笑 😄️ 😸️`），`Simplifier::Convert` 依序把等於原文的值放回原候選、其餘做成 `ShadowCandidate`，所以原詞留在最前、emoji 緊接在它後面；每個經過濾鏡的候選都轉、不設上限，詞典是人工整理的「詞 → emoji」表。librime `c95c0d2` `src/rime/gear/simplifier.cc`、[rime-emoji](https://github.com/rime/rime-emoji/tree/39d232996de79a95d7bf4b5e8533feed5326b075)（`39d2329`），2026-11-11 查。iOS／macOS 中文鍵盤的 emoji 候選位置沒有找到官方文件（[`docs/research/emoji-candidates.md`](research/emoji-candidates.md) §1）。
- **M23** 自動記住 email：AOSP LatinIME 每次上屏都學（count = 1、沒有次數門檻），不判斷 email、把 `.` `/` 當分隔，email 與網址欄位反而不出候選條，密碼欄不出、自動修正關掉不學，有遺忘曲線；SwiftKey 官方把「打你的 email」當預測還在的測試，密碼欄不預測、Incognito 不學；Gboard、Apple、搜狗只有刪除入口的說明；百度有通訊錄詞庫（已移除）；Rime、fcitx5 不自動記任意字串。沒有一家公開觸發字數與候選位置。[`docs/research/remember-strings.md`](research/remember-strings.md)，LatinIME `127336e`，2026-11-11 查。
- **M24** 聯想的按鍵：macOS 27.0.1 速成上屏後的聯想沒有預選，空白不選、只能按數字或點選（黑箱 T8）；Microsoft 繁體中文輸入法的「關聯片語」視窗用 Shift＋數字選、Space 翻頁（[Microsoft Traditional Chinese IME](https://support.microsoft.com/zh-tw/windows/hardware/input-devices/microsoft-traditional-chinese-ime)，2026-11-11 查）；librime-predict 的聯想是一般的候選選單（數字鍵選），Esc 與退格只清掉聯想、吃下不交還，標點、原樣碼與交還宿主的字上屏後不出聯想（[`predictor.cc`](https://github.com/rime/librime-predict/blob/920bd41ebf6f9bf6855d14fbe80212e54e749791/src/predictor.cc)，`920bd41`）；Gboard 速成上屏後第一下刪除只關掉聯想列、不刪字（黑箱 T11）。QIM 的取捨見 plan §2.1。
- **M25** afm-ime 用 Apple Foundation Models 做異步重排，結果只放第 2 位。`Bemly/afm-ime` `Sources/IMECore/FMReranker.swift`（`a8543a1`）。
- **M26** 可重用的滑動輸入實作：FlorisBoard v0.5.2 `StatisticalGlideTypingClassifier.kt`、AnySoftKeyboard `GestureTypingDetector.java`，皆 Apache-2.0；HeliBoard / OpenBoard 的滑動依賴閉源函式庫。`docs/research/open-source-imes.md` §1。
- **M27** Delta skin 的 `info.json`：每個方向一個 `mappingSize`（設計尺寸）與 `items`，每項有 `frame`（x、y、width、height）與 `extendedEdges`（擴大觸控範圍），依裝置與方向分版本。[Delta skin 文件](https://noah978.gitbook.io/delta-docs/skins)，2026-10-31 查。
- **M28** Keyboard Designer（Android）可自由擺放按鍵並設定尺寸、標籤、顏色、邊框；官網沒提重疊、格線與吸附。[Keyboard Designer](https://www.keyboarddesigner.com)，2026-10-31 查。

- **M30** 開源佈局格式（FlorisBoard、Trime、Hamster、AnySoftKeyboard、HeliBoard）都只支援矩形按鍵。`docs/research/open-source-imes.md` §4。
- **M31** fcitx5 table 引擎的字根提示是設定：`Hint`（Display Hint for word）開了才在候選旁接提示，分隔字預設「~ 」（`HintSeparator`）；`DisplayCustomHint` 讓組字列顯示碼表的 Prompt（字根），沒有叫出提示的快捷鍵。[`fcitx5-chinese-addons` `im/table/ime.h`](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/im/table/ime.h)、`im/table/state.cpp`，2026-11-04 查。
- **M32** 青簡（0.3.2）的兩個可選本地模型都在停鍵後（macOS 80 ms、Windows 30 ms）非同步改首選：知意（mmBERT-small 12 層加選詞頭，權重 Apache-2.0，Windows int8 ONNX 70 MB）讀游標前文，在前 5 / 9 / 18 條中挑首選；通变（自研 P2C，43 MB）在乾淨拼音 6 音節以上時把生成句排第一。作者開發集首選：通变 59.1%、知意 75.0%（含 79 MB 三元模型）。只防「翻過頁就不換」與過期結果，按空白時整句還沒換上的問題仍在。評測資料不入庫。`docs/research/qingjian.md` §4、§5。
- **M33** 青簡沒有倉頡、速成；繁體是簡體核心在出口用 OpenCC 轉字形。拼寫糾錯只算一處編輯，替換限 QWERTY 鄰鍵，每段都讀得通時照原樣、糾正只當備選；雙拼與形碼（五筆）不糾錯。英文糾錯至少 4 個字母，對 9.4 萬詞的詞表查一處編輯。譯詞表（英、日、西、越、德，約 30 MB）由 LLM 與機器翻譯離線生成，修飾鍵加數字上屏。主題是一個目錄的 `theme.json` 加圖片，可繼承另一個主題、按淺深色給變數。宣傳影片示範句中英文混輸（`jin'tian'de'me'e'ting'qu'xiao'le` → 今天的Meeting取消了）時開著通变模型。`docs/research/qingjian.md` §1、§6、§7。
