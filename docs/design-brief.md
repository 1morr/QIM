# QIM 設計綱要（Design Brief）

> 狀態：使用者已確認（2026-10-30）。本檔只寫現況：決定改了就直接改寫，不留「原寫」「取代原」「某日改」；舊版與理由記在 progress〈偏差與決定〉，影響架構的寫 ADR。標【決定】的段落是拍板過的，之後要推翻得在 `docs/progress.md`〈偏差與決定〉記一行。入門背景見 `docs/research/ime-primer.md`。

## 0. 一句話【決定】

給速成熟手的全平台輸入法：速成能連打、首選準、會學使用者的用字，各平台體驗一致。

## 1. 產品定位

### 1.1 本產品負責【決定】

- 速成連打：一串不分隔的速成碼切成字詞並排出首選（§4）。
- 候選排序與使用者學習，全部在裝置上。
- 輸入方案的抽象：核心不寫死速成，日後可加倉頡、粵拼、注音。
- 手機的觸控鍵盤，佈局用資料描述，提供畫布式的佈局編輯器（§4.6）。
- 功能分級見 §1.5。

### 1.2 本產品不負責【決定】

- 初學者教學：只提供字根提示，不做教學模式。
- 自架雲端服務：雲端 LLM 由使用者自帶 API key，QIM 不架代理伺服器、不做帳號系統（§8）。
- 多端檔案傳輸：待評估，即使做也放在主 App，不在輸入法引擎（`docs/research/ime-primer.md` §5）。
- 輸入碼裡的小工具（計算機、日期、大寫金額）與速成輔碼（碼後補倉頡中間碼篩字）：使用者用不到，重碼靠連打、學習與翻頁。

### 1.4 名稱

QIM（暫名）。

### 1.5 功能分級【決定】

依據 `docs/research/ime-primer.md` §5。

- **MVP**：速成連打；候選依使用頻率學習；手動新增詞與觸發詞；上屏學詞（含分段選字後自動造詞）；使用者詞補上詞庫沒有的詞；粵語口語詞（使用者詞、一份授權乾淨的小詞表與 HKCanCor 語料的詞；另有可選的粵典詞庫資料包，見下面「完整粵語詞庫」）；簡繁切換；中文狀態下的英文候選；組字中修改分段；畫布模型的佈局（預設 Gboard 佈局、多頁、長按、直向與橫向、淺色與深色）；按鍵放大預覽；佈局編輯器；手機的候選展開面板；字根提示；學習資料可看可刪；無痕模式。
- **之後**：聯想；雲端聯想與補全；資料包線上更新；可選的崩潰回報；英文使用者詞（打過的英文串都學，含 email、數字，出在中文組字）；輸入框上下文配合 n-gram 排序（同步層用詞級 trigram，M3 模型階梯採用）；停鍵後的小型神經模型重排（Gboard 級 1.4M，M3 模型階梯採用）；英文滑動輸入；剪貼簿歷史與同步；曲線自由手繪的按鍵、按鍵貼圖、外觀主題（鍵盤與桌面候選窗共用一份主題格式）；個人 bigram；空間模型；英文模式的預測與自動修正；依欄位類型切換；智慧標點；單手佈局；震動與按鍵音；觸控平台的實體鍵盤；Android 懸浮鍵盤；無障礙；萬用鍵（`z`：速成只用 a–y；macOS 倉頡也用 Z，`docs/research/closed-source-imes.md` §1.2；已做，行為見 §4.3）；譯詞（打中文出英文，可選資料包，詞表來源與授權開工時查）；撤銷學習；空白鍵滑動移游標；常用語；emoji 候選；詞庫匯入；完整粵語詞庫（查過：rime-cantonese 授權鏈不明不用，先補 HKCanCor 的詞；照粵典較嚴的非商業條款，把它的詞頭另建成可選的詞庫資料包 `quick-lexicon-words-hk`，預設詞庫不含、可整份拿掉，`docs/research/facts-tables.md`；授權允許商用的完整粵語詞庫仍沒有）。
- **待評估**：中文滑動輸入；語音輸入；多端檔案傳輸；句中英文混輸（§4.7）；腳本外掛（網頁版驗收後再定，理由見 `docs/research/cyime.md` §6）。
- **不做**（M3 模型階梯量過、沒過門檻，理由與重評條件見 `docs/research/model-ladder.md`）：LLM 候選優化（雲端 LLM 與 Foundation Models 的重排）；青簡級 23M 神經模型；不設預算、可選下載的詞級 trigram。速成四種修正的容錯（§4.8，量過、沒過門檻，重評條件見 `docs/research/tolerance.md`；觸控鄰鍵讀法另行採用）。

## 2. 使用者與情境【決定】

- 主要使用者：會連打的速成熟手，港澳、寫繁體、會打粵語口語、中英混打，在手機和電腦之間切換。
- 次要（之後）：倉頡、粵拼、注音的使用者，透過新增輸入方案支援。
- 不是主要對象：初學者，只靠字根提示照顧。

## 3. 平台範圍與順序【決定】

網頁 prototype → 平台可行性實驗 → 智慧候選、輸入增強、佈局編輯器（網頁）→ 使用者驗收 → macOS → iOS → Android → Windows → Linux。

- 先在網頁做完所有核心功能：功能大多在共用核心裡，平台殼開工時核心介面已穩定，每個平台一次接上全部功能，不必做半成品再慢慢修改（`docs/roadmap.md`）。
- 平台可行性實驗排在智慧候選之前：iOS 限制最多（記憶體上限不公開、沒有 marked text、密碼欄換系統鍵盤，`docs/research/facts-platforms.md`），模型大小要先知道放不放得下。
- macOS 是第一個平台殼：開發機就是 Mac，能用 `orca computer` 實跑驗證，沒有記憶體上限，適合打通核心與平台殼的界線。
- 網頁驗不到的部分（真實 App 內的行為、各平台讀上下文的差異、手機真實延遲）仍可能在平台里程碑修改。
- Android、Windows、Linux 依序。

## 4. 輸入行為

### 4.1 字集與字形【決定】

- 輸出以繁體為主，字集涵蓋 Big5 加 HKSCS；簡體輸出靠 OpenCC 轉換。
- Unicode 擴展區的罕用字不出現在連打候選，只在單字查詢時出現。
- 繁體模式下，HKSCS 收的簡體字（「门」「农」「阳」「头」）排在同碼的繁體字之後，像 macOS 速成；有開關、預設開（§7），關掉時照字頻混排；不過濾，選兩次照常成首選；簡體模式不受影響（使用者 2026-11-11 決定）。「簡體字」只算 Big5 沒有、只靠 HKSCS 進連打字集，而且 OpenCC 認定只是簡體寫法的字（判定見 plan §4.1）：繁簡同形的字（人、日）與本身是正規繁體字的字（台、后、里、干、面、系）都在 Big5，不算；香港寫法（温、户）、香港《常用字字形表》的標準字形（够：字表收「够」不收「夠」，`docs/research/facts-tables.md`）與粵語用字（吓、响）也不算；「恒」不算香港標準字形（字表的正字是「恆」），照算簡體字（使用者 2026-11-11 要求對照字形表再核，結果見 `.scratch/m3/issues/19-simplified-after-traditional.md` 的 Comments）。粗口字「𨳊」照字頻、不另處理。
- 字形跟系統字型。
- 用字取常見寫法（說、溫、群、衛、搵），不用香港寫法（説、温、羣、衞、揾）：語料轉成香港繁體後換回常見寫法（plan §4.3）。使用者決定（2026-11-04）。詞庫也一樣（「羣組」→「群組」、「觀衆」→「觀眾」，plan §4.2）。
- 不同碼、兩種寫法都常見的字兩種都收，打哪個碼出哪個，兩種寫法的字頻、詞頻與 bigram 相同（並存寫法：裏裡、線綫、啟啓、麵麪、床牀、污汙、泄洩、戶户、敘敍、臥卧、枱檯、鈎鉤、濕溼、抬擡、粽糉、枴柺、囱囪，plan §4.3）；要選一邊時（簡轉繁的輸出、基準題目）用代表寫法：線、啟、麵、床、戶、敘、臥、裏、污、泄、枱、鈎、濕、抬、粽、枴、囱。「着／著」「臺／台」「菸／煙」只單向：「着」「臺」「菸」的詞另收「著」「台」「煙」的寫法（隨着、隨著；臺灣、台灣），反過來不行（著名不寫成着名、台州不寫成臺州），語料照原文寫，兩字的字頻各算各的。罕用的蔘痹檐幺睾繮嫺齶鮎不動。使用者決定（2026-11-05；後 6 組雙向與「臺」「菸」單向是後來的補漏）。已知限制：簡體模式打「隨著」的碼出「随著」（OpenCC `hk2s` 沒有「著→着」），使用者決定不修（plan §4.3）。
- 字形偏好（讓使用者自己選常見寫法或香港寫法）之後的里程碑再做，M1 不做（2026-11-05 使用者問到）。

### 4.2 取碼【決定】

- 速成碼取倉頡碼首尾兩碼；同時接受由倉頡三代與五代推導出的速成碼（Microsoft 預設三代、macOS 用五代，據 [維基百科](https://zh-yue.wikipedia.org/wiki/%E5%80%89%E9%A0%A1%E8%BC%B8%E5%85%A5%E6%B3%95)，二手來源）。
- 速成碼在建置資料包時推導，存成速成輸入方案自己的碼表；倉頡碼不是速成的合法輸入碼（ADR 0003）。
- 字根提示預設顯示五代，可改三代。

### 4.3 桌面鍵盤操作【決定】

參考 macOS 與 Windows 內建速成，加上連打。

| 鍵 | 行為 |
| --- | --- |
| 空白 | 上屏首選（翻頁後也一樣） |
| 1–9 | 選對應候選 |
| `-` / `=`、PageUp / PageDown | 翻頁 |
| Enter | 把輸入碼當英文原樣上屏；已選定的分段上屏字詞，其餘上屏輸入碼 |
| Esc | 清除輸入碼 |
| ← / → | 組字中移到前一段或後一段，候選改列該段的字詞；← 從最後一段開始，→ 走過最後一段回到整串 |
| Tab | 組字中在候選旁列出或收起字根提示；沒有組字時交還宿主 |
| Shift（單按） | 切換中英文。組字中預設照 Rime：左 Shift 留著輸入碼當英文接下去（臨時英文），右 Shift 先上屏整個組字（同一直按空白）再切換；設定可改成左右都先上屏或左右都留碼（§7）。沒有組字時兩邊都只切換。英文狀態下按鍵直接交給宿主 |
| ↓ / ↑ | 組字中打開或收起候選展開面板 |
| Shift+Delete、Ctrl+Delete | 組字中撤銷首選（翻頁後是這頁第一個）的學習（§4.5）；沒有組字時交還宿主 |
| `'` | 組字中在目前位置插入分隔記號（手動分隔）：這裡一定要斷字，詞只在它落在兩字的碼之間時跨過它，組字裡顯示成 `'`；已經以它結尾時不再加。沒有組字時照打 `'` |
| 標點 | 組字中先上屏整個組字再接標點；沒有組字時直接上屏標點 |
| 大寫字母（Shift＋字母） | 組字中先上屏整個組字再接那個字母；沒有組字時照打 |

- 組字中每個鍵都吃下，不交還宿主：交還的話宿主照打那個字元，組字卻還留著。表上沒有的鍵（Delete、Home、End）與 Ctrl / Cmd / Alt 組合鍵（Cmd+C、Option＋字母也是）組字中吃下不動作，不然 Cmd+V 貼進輸入框而組字還在。
- 萬用鍵 `z`（§1.5）：忘了某一碼時用它代替，每個 `z` 剛好代一碼，放在首碼、尾碼都行（`hiz`、`hzo` 首選都是「的人」），單獨一個代任一個一碼的字；同一個字或詞的碼裡 `z` 不多於記得的碼、最多兩個。組字裡顯示「＊」。和改前的差別：組字中按 `z` 原本吃下不動作（等於少打那一碼，整句一定打不出），現在接進輸入碼；沒有組字時按 `z` 原本交還宿主照打 z，現在開始組字，要打英文 z 時按 Enter 原樣上屏或切英文。選了的字學的是它實際的碼。這是比對模式，不是容錯：不按 `z` 時候選完全不變，沒有組字時的 `z` 在中文狀態本來就少用、Enter 仍打得出，所以不另設開關。觸控鍵盤的 z 鍵照 Gboard 標「重」，點了同樣是萬用鍵。dev 切分上（`docs/research/wildcard.md`）：整句裡一碼換成 `z`，整句首選約是原樣的七成；只打一個字時很難找，`az` 這類平均對得上約 750 個單字，首選只對 1–2%、平均 5–10 次修正；期中檢查使用者決定不補強。打含 `z` 的輸入原本每鍵比平常慢約 14 倍（空白學習資料的全部 p95 約 1.07 ms 對 75 µs），超過 M4 的每鍵延遲上限 1 ms（實測）；改成候選列重用逐鍵算過的開頭各段後，空白的全部 p95 約 0.24 ms、學過的約 0.38 ms（第一碼換成 `z`，Apple M6），`bench --check` 照同一組上限擋。
- 單按 Shift：按下到放開 500 ms 內、中間沒有按下或放開別的鍵才算，Shift＋字母是大寫、Ctrl＋Shift 不算；左右一起按時從第一個按下計時，先放開的那邊算（librime `ascii_composer` 同值同做法）。左右由殼分辨。預設照 rime-prelude：左 `inline_ascii`、右 `commit_text`（`docs/research/facts-rime.md`）；使用者 2026-11-05 試用後決定，推翻原本的左右都先上屏。先上屏的 Shift 上屏整個組字，和 Rime 不同：Rime 的 `commit_text` 是 `ConfirmCurrentSelection`，只確認最後一段選的候選，沒確認的碼在英文模式下變原樣留在組字（`docs/research/facts-rime.md`）。
- 臨時英文（照目前發佈版 librime 的 `inline_ascii`，≤ 1.17.0，`docs/research/facts-rime.md`）：沒選定的輸入碼原樣變成英文留在組字，沒有候選；已選定的分段照舊在前面（發佈版 librime 也留著）。之後的可見字元（數字、`-` / `=`、標點、大寫）與空白照原樣接上去，可以一路打出 `hello world`；Enter 上屏英文；退格刪光或 Esc 放棄。再按留碼的 Shift：英文整串當中文的輸入碼回到中文組字（沒動過就是原樣還原）；英文含方案字母、萬用鍵與分隔記號以外的字元（空白、數字、大寫、標點）時 QIM 的中文組字裝不下，改上屏英文（發佈版 librime 把它們切成原樣的分段）。觸控鍵盤輸出的字（標點、數字、表情、「常用」頁的短句，§4.4）也照原樣接上去。按先上屏的 Shift 上屏英文。以上都回中文。方向鍵、翻頁鍵、Tab、↑ ↓ 吃下不動作（發佈版 librime 的 ← / Home 移游標、Delete 刪游標後的字，QIM 沒有輸入碼內的游標）。
- 臨時英文照使用者用的小狼毫，也就是目前發佈版 librime（≤ 1.17.0），不照未發佈的 master（`74bd5dc4` 起空白上屏英文加一個空白、打過字或退格過再按留碼的 Shift 就上屏，只在 master 與 rolling prerelease，`docs/research/facts-rime.md`）；使用者 2026-11-05 決定。風險：librime 1.18 發佈、小狼毫更新後，使用者的小狼毫會變成 master 的行為，QIM 跟不跟到時再決定。選定的分段遇退格、Esc 不學發佈版（發佈版第一下退格把選定的分段拆回英文、Esc 只清最後一段）：退格刪光英文時最後選定的分段放回來重選，同中文的退格；Esc 整個放棄。
- 手動分隔（使用者 2026-11-05 決定）：照 Gboard 速成組字中的「'詞」鍵（[黑箱基線](research/blackbox-baseline.md) T18：`an'r` 首選仍是門口）；字元用 Rime 拼音方案的分隔符 `'`（`docs/research/facts-rime.md`），速成、倉頡的碼不用它。分隔記號留在輸入碼裡、算在前一段的碼尾，同 Rime 顯示在組字裡：`mi'r` 顯示「一戈'口」。分隔記號是「這裡一定要斷字」：單字的碼裡不能有它；詞庫的詞與使用者詞可以跨過它，條件是它剛好落在詞內兩字的碼之間（詞的每個字的碼對齊輸入碼，字有幾個碼時任一種拆法都算）。照 Rime 速成（quick5 用 `script_translator`，每個字的碼當一個音節，`docs/research/facts-rime.md`），使用者 2026-11-05 決定，推翻原本的「段不跨過它」：分隔落在詞內的字界上時，詞跨過去不違背使用者要的斷點，不跨反而讓 `vi'vdjg`「絃樂室」變成「幾好塞」（公開語料在正確字界插一個 `'`，1429 例中分隔後變錯的由 81 例降到 0）。所以 `mir` 的首選「一台」是 `m` + `ir`，`mi'r` 不出「一台」；`an'r` 的「門口」（`an` + `r`）照樣是一個詞、仍是首選。QIM 沒有輸入碼內的游標，所以分隔記號和字母一樣接在輸入碼最後，有目前分段時也回到整串。退格先刪分隔記號；選了它前面的字詞，分隔記號跟著選定的分段走；Enter 原樣上屏含分隔記號的輸入碼；臨時英文裡它和其他字元一樣接在英文後，按回留碼的 Shift 時照樣回中文組字，但英文裡連著兩個時中文組字打不出，改上屏英文。學習與自動造詞記的碼不含分隔記號（同 Rime 使用者詞典的碼），所以 `mi'r` 選兩次的字詞，不分隔打 `mir` 也成首選。
- 「上屏整個組字」和一直按空白相同：已選定的分段，接著逐次取剩下的輸入碼的首選，沒有字的碼原樣上屏。移到某一段時按空白也是上屏整個組字。
- 參考：組字中按標點，macOS、iOS 速成與 Gboard 都先上屏首選再出標點（[黑箱基線](research/blackbox-baseline.md) T18）。Enter、大寫字母照 librime express_editor：Return 是 `CommitRawInput`（選定的段上屏字、其餘上屏原碼），方案以外的可見字元是 `DirectCommit`（先上屏組字、字元照打）。macOS、Gboard 的 Enter 上屏首選，macOS 的 Shift＋字母把整串改成英文，都不學：要首選有空白，要英文有 Enter。
- 標點預設全形：`,` `.` `?` `!` `;` `:` `(` `)` `[` `]` `{` `}` `<` `>` `\` `^` `_` 依序轉成 ， 。 ？ ！ ； ： （ ） 「 」 『 』 《 》 、 …… ——，取 rime-prelude `punctuation.yaml` `half_shape` 每鍵第一個是全形的選項，不出標點選單。緊接在數字後的 `.` `:` 保持半形（§4.7）。其他符號上屏半形：引號要配對（智慧標點，§4.7）；`/`（Rime 是「、」，和 `\` 重複，留給網址與分數）、`$`（Rime 是「￥」，香港用 $）不學 Rime；其餘 Rime 的第一個選項就是半形。`-` / `=` 是翻頁鍵，沒有組字時照打。
- 英文候選：輸入碼剛好是完整英文單字時放第 2 位，不搶首選；不容錯、不補全，糾錯與預測只在英文模式（§4.7）。第 3 碼起才出（1–2 碼的英文字和單字的碼撞得太常，macOS 速成也是第 3 碼起，[黑箱基線](research/blackbox-baseline.md) T7）；專有名詞照大小寫顯示（English）。選它時上屏那個英文字（照詞表的拼法），和 Enter 一樣不學，選幾次都不會變首選。macOS 對 `ipad` 列出 iPad、ipad 兩個，QIM 只佔第 2 位一格，有全小寫拼法就取它（`may`），沒有才取大寫（iPad）；要原樣的小寫可按 Enter。
- 組字中顯示已打的字根（如「日弓口」），已選定的分段顯示字詞；候選旁平常不顯示碼。
- 字根提示：組字中按 Tab，目前頁每個候選旁逐字列出倉頡碼的字根與字母（「日弓(an) 口(r)」，多個碼以「／」分隔），再按一次收起，組字結束也收起；預設五代、可改三代（§4.2）。參考 fcitx5 table 引擎：組字列顯示字根、候選旁以「~ 」接提示，但它是設定開關、沒有快捷鍵（`docs/research/facts-products.md`）；黑箱基線沒有測競品的字根提示。選 Tab：組字中它本來就吃下不動作，不必加修飾鍵，也不佔分段用的 ← / →。

### 4.4 手機觸控鍵盤【決定】

以 Gboard 速成佈局為底（鍵位、符號頁、配色照 Android 上的實測）：

- 字母鍵主標籤顯示字根，角標顯示英文字母（AnySoftKeyboard、倉輸入法的倉頡鍵盤做法）。
- 長按字母鍵只彈出英文字母，不含數字（使用者 2026-11-05 決定）。
- 數字列（同 Gboard 的 Number row）預設不顯示，設定可開；打開時字母頁上方多一排數字，點一下輸入數字。
- 第三排左邊是 Shift（同 Gboard 速成）：點一下，字母鍵標籤換成大寫字母，下一個字母鍵直接輸入大寫英文字母（不經組字），打完自動回到字根；按了別的鍵（標點、空白、刪除、切頁）也回到字根（Gboard 實測）；快速點兩下鎖定大寫，再點一下解除，鎖定時按別的鍵不解除。長按字母鍵一律出小寫。組字中照 Gboard 換成分隔鍵：主標籤「'詞」，點一下同實體鍵盤組字中按 `'`（§4.3，使用者 2026-11-05 決定，推翻原本的組字中照樣是 Shift）；沒有組字時才是 Shift。觸控的 ⇧ 是大寫鍵，不是 §4.3 的單按 Shift：不切中英、不受「組字中單按 Shift」的設定影響（那個設定只管實體鍵盤的左右 Shift 與佈局裡的中英鍵）。
- 符號頁照 Gboard：?123（數字與常用符號）、=\<（更多符號）、12/34（數字鍵盤）。觸控的標點鍵一律照鍵上的字輸出，不像實體鍵盤由核心猜全形半形（使用者 2026-11-05 決定，推翻原本的觸控標點等同實體鍵盤）：字母頁的「，」「。」全形；符號頁 Gboard 實測打全形的「：；！？（）［］」標全形、打全形，其餘 ASCII 標點（含底排的 `, .`）半形，同 Gboard（使用者決定：以 Gboard 實測為準）。中文、英文直通都一樣；已知限制：英文直通時觸控打不出半形的 `? ! : ; ( )`，預設觸控佈局沒有中英鍵，只有接實體鍵盤時才進得了英文直通，那時用實體鍵盤打（使用者 2026-11-12 要求觸控加中英鍵與英文鍵盤，排在 M4，roadmap〈M4 輸入增強〉）。組字中先上屏首選再接那個字，臨時英文中接在英文後面。打完符號留在符號頁，按「返回」才回字母頁。
- 逗號鍵長按進「常用」頁（表情與寫死在佈局裡的常用短句，自訂頁面的示範；使用者自己存的常用語從候選列的「常用語」鍵叫出，plan §3.1），代替 Gboard 逗號鍵的表情入口；句號鍵長按出 Gboard 同樣的 16 個符號，預設「……」。
- 候選列單列、可左右滑，右側展開鍵一次看全部候選（候選展開面板因此列入 MVP）。
- 空白上屏首選；英文候選規則同 §4.3。
- 按鍵時顯示放大預覽；點組字裡的某一段可改該段。
- 點候選選字；長按候選列出或收起字根提示，同桌面的 Tab（§4.3），不選字；按住後滑動兩者都不做。
- 候選列不因背景模型的結果改動首選（ADR 0005）。

### 4.5 學習與排位【決定】

- 候選依使用頻率逐步前移：同一個輸入碼選同一個候選兩次即成首選；兩次要在一年內（日曆時間，由殼給日期），太久以前的那次不算，偶然選過的不因多年累積成首選；上屏後緊接著按退格，撤銷這次上屏的學習（照 Rime；有聯想時這下退格也刪字並撤銷，不照 librime-predict 先只收起聯想）；兩台裝置各選一次也算兩次（使用者 2026-11-12 決定，M4 實作；原本間隔多久都算）。舊習慣隨使用次數衰減；一年沒用的條目停用、不刪（殼的時鐘可能錯，改回來就恢復作用，使用者 2026-11-12 決定）；學習資料有條目上限，超過時淘汰最久沒用的（照 LatinIME，plan §2.4）。「兩次」只算單獨打這個輸入碼時選它，連打句中用過的不算（句中用過的只在連打裡加分）。參考 librime 的衰減計數（`docs/research/facts-rime.md`），參數用首選字基準調。
- 學過的字詞在更長的連打裡也加分，不只在輸入碼完全相同時生效；個人分只加不減（libime 做法，`docs/research/facts-products.md`）。
- 自動造詞：分段選字上屏後立即學成使用者詞，下次先排第 2，再選一次成首選。
- 手動新增的使用者詞在打它的觸發詞時一定是首選。
- 撤銷學習：學錯的候選能清掉它學到的，詞庫原有的詞回到原位、自動造詞不再出，再選可以重新學；不做永久屏蔽（CyIME 的永久屏蔽被使用者評為偏離預期，`docs/research/cyime.md` §4）。手動加的詞與常用語只清計數、詞留著。桌面是組字中 Shift+Delete 或 Ctrl+Delete，清首選、翻頁後清這頁第一個（librime 的預設高亮，`docs/research/facts-rime.md`）；成熟產品沒有共通的「刪第 N 個候選」按鍵（`docs/research/facts-products.md`），所以釘在第 2 位的自動造詞桌面要等它成首選才清得到，觸控的手勢跟 M5 重做候選列一起定。範圍細節見 plan §2.4。
- 學習可在設定關閉或重置。
- 無痕模式：密碼欄與帶「不要個人化學習」旗標的欄位自動進入，也可從候選列按鈕手動切換。
- 學習資料在主 App 列出，可搜尋、刪除、全清。

### 4.6 佈局與編輯器【決定】

- 佈局是畫布：每個按鍵各自有位置、大小、旋轉、形狀、上下層順序、外觀與動作（ADR 0004）。預設是 Gboard 佈局，也是這種資料。
- 一份佈局可依裝置與方向有多個佈局版本（手機、平板；直向、橫向），每個按鍵有淺色與深色的顏色，並帶無障礙標籤。
- 允許搞怪：按鍵可以重疊、亂序、超出常規。重疊時上層優先；各平台用同一份點擊判定。
- 形狀：長方形、圓角、橢圓、旋轉、拖頂點改任意多邊形。外觀：每鍵顏色、透明度、文字大小與位置。曲線自由手繪、按鍵貼圖、外觀主題是之後的功能。
- 編輯器：拖動、縮放、旋轉、改形狀、調上下層、多選、復原；設定輸出、長按、滑動、切頁；邊編輯邊試打；匯入匯出。只寫一份網頁版，在各平台主 App 內嵌，桌面可用滑鼠編輯（ADR 0004）。
- 對齊：格線與吸附預設開，欄數列數可調並存進佈局檔；可一鍵切完全自由，也可按住修飾鍵（手機用雙指）暫時不吸附；拖動時顯示與其他按鍵對齊的參考線。
- 安全底線：只擋三種情況：檔案壞掉；頁面之間切不回有字母的頁面；iOS 需要切換鍵盤鍵時卻沒有。重疊、被蓋住、超出畫布、缺字母只警告。主 App 永遠有「恢復預設佈局」。
- 單手：內建左手、右手兩份預設佈局。懸浮鍵盤只在 Android 做；iOS 不能畫到鍵盤外（`docs/research/facts-products.md`）。

### 4.7 英文模式與欄位類型【決定】

- 英文模式有單字預測、自動修正（退格可還原）、Shift 與句首大寫。自動修正只在英文模式作用。自動修正與句首自動大寫各有開關，預設關（§7）。
- 英文使用者詞（使用者 2026-11-12 決定，照 LatinIME 上屏都學）：核心看得到送出去的英文串都學（英文直通、臨時英文、選了的英文候選；英文模式接上後含它上屏的），不另認 email，數字、電話、卡號照學；無痕、密碼欄、學習關掉不學（§8、§4.5）；4 個字元起才學。出現門檻：英文詞典沒有的串一年內打過 2 次，中文組字打完整串時排第 2（同英文候選）；打過 3 次又是最常用的 20 條之一，中文組字打它開頭的字母（第 3 碼起）就給（前綴補完，誤觸率逐條累加所以限 20 條）。詞典有的詞不受門檻，照英文候選出、學習只讓它排前，也不進中文的前綴補完（協調者 2026-11-12 決定，免得 that、have 把常寄的 email 擠出去）。沒到門檻的照樣匯出、同步，到條目上限時最先淘汰。英文模式的建議列（M4 第二期）打開頭就補完、照使用頻率排；桌面的英文仍是直通、沒有建議列，桌面學到的只出在中文組字。規則與數字的理由見 plan §2.1、§2.4 規則 4、5。
- 中文狀態的英文候選只認拼對的完整單字，不容錯、不補全：速成連打兩個字就是 4 個字母，隨機 4 個字母約四成與英文詞只差一處（`docs/research/facts-tables.md`），容錯會常佔第 2 位、打亂熟手「按 2 選某字」的習慣；拼對的完整單字隨機撞到不到 1%。
- 句中英文混輸（一串輸入碼裡夾英文詞，如「今日有meeting」）待評估：拼音靠「拆不成合法音節」認出英文，速成沒有這個訊號，只能比語言模型分數，誤判風險高；M4 當實驗，同樣只認拼對的常見詞，純中文句子的首選與修正次數不退步才採用。
- 欄位類型：email、網址預設英文模式並關自動修正；數字欄開數字頁。
- 智慧標點（可關）：數字後的句點與冒號用半形（逗號照舊全形）；成對符號自動配對；英文模式連按兩下空白輸出句點。
  - 數字後半形（使用者決定）：游標前的字（前文的最後一字，含殼給的前文，plan §2.1）是半形數字時，`.` `:` 直接上屏半形，不待定、不出候選（「3.5」「12:30」）。再按一次照一般規則：前一個字已不是數字，所以是全形（`3` `.` `.` 是「3.。」）。要全形就關開關。同 librime `digit_separators` 的預設 `.:` 加 `digit_separator_action: commit`（`docs/research/facts-rime.md`）；不學 Rime 預設的待定、再按一次改全形（使用者在小狼毫試過後決定，2026-11-05）。
  - 逗號照舊全形（使用者決定，2026-11-05）：中文裡數字後的逗號多半是句子的逗號（「共3，」「第1，第2」），「1,000」這類千分位少見，要打就切英文（單按 Shift，§4.3）；關開關沒用，它只讓數字後的句點、冒號也變全形。Rime 現在的預設也不含逗號：2025-01 加入時含 `,`，2025-11 拿掉回到 `.:`。上游沒寫理由；推斷是回到長期的預設，因為 2025 年以前 librime 一直只轉 `.` `:`（`docs/research/facts-rime.md`）。
  - 「緊接在數字後」看前文的最後一字：殼給了前文就看它，所以輸入框原有的字、滑鼠移動游標都看得到；之後核心送出去的字（上屏的字、交還宿主的可見字元）接在後面。交還宿主的其他鍵讓前文作廢、當成數字結束，含方向鍵與留給宿主的組合鍵（Ctrl+B、Cmd+V；Rime 不記方向鍵，不學：游標已離開數字），等殼再給。只改鍵盤狀態、不送字元的鍵不算數字結束：單按 Ctrl、Cmd、Alt、CapsLock 這類修飾鍵，觸控鍵盤的切頁與 ⇧（Rime 也不記沒有字元的鍵）。無痕時殼不給前文，只看核心自己送出去的字。觸控鍵盤的標點照鍵上的字輸出，不套這條規則（使用者決定）；它的數字鍵算數字，數字之後接實體鍵盤的 `.` 照樣半形。和 Rime 的差異：Rime 的 `is_after_number` 只看上一筆上屏紀錄是直接打出的（`thru`、`raw`）且以數字結尾，QIM 看任何上屏的字以半形數字結尾，所以選了自加的「MP3」這類以數字結尾的詞之後，QIM 的 `.` 是半形、Rime 是全形（`docs/research/facts-rime.md`）。留碼接英文（臨時英文，§4.3）中的數字與標點照原樣接在英文後，不套這條規則。

### 4.8 容錯【決定】

依據 `docs/research/ranking-techniques.md` §5 與青簡（`docs/research/facts-products.md`）。

- **速成不做四種修正的容錯**（量過，沒過〈容錯採用門檻〉）：照下面的設計，四種修正各自都讓打錯碼的句子多讀回一些，但合起來修正次數只少 4–6%（門檻要少 10%）、原樣正確卻被改錯 1.8–2.6%（上限 1%），沒打錯的集合也退步；單字不修讓口語打錯的句子最多只救得回約兩成。數字與重評條件見 `docs/research/tolerance.md`（`docs/research/facts-products.md`）。下面幾條留作重評時的設計。
- **觸控鄰鍵讀法**（照 Gboard 速成，使用者 2026-11-14 決定採用、預設開，推翻「單碼不列鄰鍵的字」）：只對觸控，觸控點一下的按鍵機率裡、機率至少是打出的字母 0.2 倍的鄰鍵字母（每碼最多兩個）換進輸入碼，一段碼換一碼、單字也換，換一碼扣 `ln(打出的 ÷ 換成的)`；換出來的讀法從候選列第 2 格起插、最多 2 個，原樣讀法照舊當首選（點在交界也不搶：搶首選的改錯都超過 1%）。實體鍵盤不換；萬用鍵不換、也不換成萬用鍵。選了它學的是換過的碼。量到觸控模擬淨少 12.5% 修正、打錯的句子 35.5% 在第一頁找回整句、單字點錯的 66% 在第一頁、改錯 0；代價是點對鍵時修正多 5.6–8.4%（〈容錯採用門檻〉沒打錯不退步那條沒過，使用者看過數字後採用）。數字見 `docs/research/tolerance.md`〈Gboard 式的鄰鍵讀法〉。
- 預設相信使用者：原樣讀得通就照原樣排，修正過的讀法帶懲罰，通常只當備選。
- 容錯可在設定關閉，預設開（§7）：速成的容錯就是觸控鄰鍵讀法；英文模式的容錯另由它的票定。
- 速成每字只有兩碼，幾乎每個兩字母組合都是合法碼，打錯或漏碼多半變成另一個合法字（漏打 `anr` 的 `n` 就是「問」的 `ar`）。所以四種修正的容錯單字不修，只在詞與句層靠詞庫和上下文判斷「原樣讀不通、改一處就通」；觸控鄰鍵讀法不搶首選，單字也列。
- 按鍵位置：觸控用點擊位置算各鍵的機率（空間模型）；實體鍵盤用實體鍵盤的幾何算鄰鍵（含上下排與斜角），按實體鍵位、不按字母，換配列照樣適用。中文模式整個當美式鍵盤：字母與標點都照實體鍵位（`KeyboardEvent.code`），換 Dvorak、AZERTY 等配列時中文模式的手感跟美式一樣；英文直通照配列（使用者 2026-11-12 決定）。臨時英文也是英文，同樣照配列（使用者 2026-11-12 確認）。
- 機制所有方案共用，允許哪些修正（鄰鍵替換、漏碼、多碼、兩碼對調）、懲罰與啟動條件由方案各自設定並用自己的基準調：倉頡長碼稀疏，單字層也可容錯；拼音、粵拼另有模糊音與簡拼。

## 6. 核心引擎

- 【決定】自己寫核心，參考 libime 與 librime 的做法但不依賴它們（ADR 0001）。
- 【決定】核心與平台殼分離：核心是純邏輯，收輸入碼、回候選；平台殼負責註冊、事件、畫面、上下文。

## 8. 隱私與安全【決定】

網路是正式功能，不是例外；以下三條是硬限制：

1. 核心打字永不依賴網路。打字、排序、學習在裝置上完成；雲端結果一律非同步，斷網或慢時打字與本地候選不受影響。
2. 密碼欄與帶「不要個人化學習」旗標的欄位：不學習、不讀上下文、不記剪貼簿、不送雲端。
3. iOS 不要求完整取用權限：沒開時打字與學習照常（鍵盤可寫自己的容器）；開了才有雲端、同步、剪貼簿歷史（App Review 4.4.1，`docs/research/facts-platforms.md`）。

其他：

- 雲端功能預設開啟，但只有使用者在設定裡接上雲端服務（填入 API key）後才實際連線；雲端給的候選標示來源。
- 雲端 LLM 由使用者自帶 API key，支援 OpenAI 相容介面與 Anthropic 介面；QIM 不架代理服務。
- API key 存系統的安全儲存（Keychain、Android Keystore 等），不存明文。
- 送出前遮蔽 email、電話、卡號這類字串；可設每日請求上限，超過就停止送出，打字不受影響；可排除指定 App，平台拿不到宿主識別時在設定頁註明。
- 送往雲端的內容：游標前最多 50 字、目前輸入碼、lattice 的前 9 條路徑；不送游標後的文字。QIM 不在任何伺服器保存；模型供應商的保存規則依其政策，在設定頁註明。M3 模型階梯量過，送 200 字沒有比 50 字好到門檻的 1.0 點，改成 50 字（`docs/research/facts-model-ladder.md`）。
- 雲端 LLM 重排在 M3 模型階梯沒過門檻，暫不做（§1.5）：要比已採用的本地停鍵層（1.4M）再多 3.0 點，flash 在舊基線只多 2.0 點，在新基線重量也只多 2.4 點（比基線 +7.9、延遲與費用都過）；重評條件見 `.scratch/m3/issues/22-cloud-rerank.md`。本節的規則留給重評或之後的雲端功能。
- 不收集使用統計。崩潰回報可選、預設關閉，只送堆疊不送輸入內容。

## 9. 效能與品質指標

【決定】

- 延遲：在最低階目標裝置上，每按一鍵到候選更新，目標 ≤ 50 ms，上限 100 ms（研究推出的工程預算，`docs/research/ranking-techniques.md` §8.5）。M2 在 iPhone 18 Pro Max 的鍵盤擴充實測每鍵 p95 64 µs、最重的選開頭一段 p95 0.79 ms（`docs/research/facts-platforms.md`）；低階機沒量。M3 加上詞級 trigram 後這台 Mac 每鍵 p95 約 1.4 倍（同一程序比 43 → 62 µs）、選開頭一段 0.75 → 1.2 ms，iPhone 上沒重量。
- 記憶體：iOS 鍵盤擴充的 footprint 峰值留在系統的記憶體警告線以下，不靠收到警告後釋放。M2 實測（只量了 iPhone 18 Pro Max、iOS 27.2）上限 177 MB、約 142 MB 收到警告；核心加六份資料包載入後 79 MB，M3 的模型峰值增量 ≤ 60 MB（roadmap〈M3 的模型階梯實驗〉）。M3 加上詞級 trigram 預算版：載入後約 87 MB（再載入它留下 +5.6 MB、峰值 +20.4 MB，建 `Engine` +2.3 MB）；放寬版峰值 +71 MB 超過上限，沒用（`docs/research/facts-platforms.md`）。旗艦機的上限可能比低階機高，低階機在 M8 量（`docs/research/facts-platforms.md`）。
- 首選正確率：首選字基準。把真實繁體 / 粵語句子機械轉成速成碼，讓核心連打，量整句首選正確率與字正確率；`mir` → 一台、`anr` → 門口等案例為固定必過題。改核心或資料包時必跑，答錯數不得上升。
- 修正成本：長句首選常會錯（速成每字資訊少，`docs/research/facts-products.md` 的拼音數字可參考），所以同時量打一句平均要選字和翻頁幾次、每字按鍵數，以及打字途中首選跳動多少；修正次數不得上升（plan §5.2）。
- 基準語料：中文維基與粵語維基抽樣（CC BY-SA 4.0，基準檔單獨標註授權，只放測試資料、不打包進 App）；口語語料（§5.2）；使用者 Rime 的學習資料（詞與上屏次數，M1 就要有，只在本機）與選填的真實句子；使用者回報的案例為固定必過題，持續增加。品質判斷以口語與個人集為主，維基只防退步。

- 【決定】使用者目前沒有付費 Apple Developer 帳號：macOS 里程碑先用本機簽章自用；iOS 上架前申請帳號，之後 macOS 改發簽章、公證過的 `.pkg`。自動更新與 Homebrew cask 之後再做。
- 【決定】iOS：App Store。Android：Play Store，GitHub Releases 同時發 APK；F-Droid 之後。Windows：簽章安裝檔；winget 之後。Linux：框架（Fcitx5 或 IBus）與打包到 Linux 里程碑再定。
