# 候選模型分三層，慢的模型不能動首選

候選模型分成同步、停鍵、雲端三層（plan §2.7）。同步層在每次按鍵的 Viterbi 內執行，決定首選；停鍵層與雲端層只在停鍵後非同步重排，結果最高到第 2 位，只決定名次、不寫回分數。熟手是連著按空白上屏的，首選在按下前一刻變動就會打錯字（afm-ime 的理由），而每鍵延遲預算（brief §9）也裝不下神經模型或 LLM。Gboard 的同步解碼、afm-ime 與青簡的非同步重排都是這個分法。分數不寫回，是因為神經分數只在同一串按鍵內可比（青簡踩過）。

## Considered Options

- 只有 n-gram 加雲端 LLM：實作最少，但中間檔完全沒量過，離線與沒填 API key 時也沒有上下文判斷。改由模型階梯實驗（plan §7.8）決定每一層用什麼。
- 讓重排結果能改首選：正確率可能更高，但要等模型回來才敢按空白。之後若實驗顯示值得，再限定在停鍵夠久的情況評估。

## Consequences

- 準確度主要靠同步層和個人模型，慢模型只是補強，沒網路、沒 API key 時體驗不會斷崖下跌。
- `qim-core` 不開執行緒，推論不放在裡面；採用小型神經模型時要另建 crate。
