# 跨裝置合併：各台分開記的次數、存雜湊的墓碑、以合計次數為版本

學習資料的跨裝置合併在核心定稿，平台殼之後只做傳輸、不改格式（brief §7、plan §2.4〈跨裝置合併〉，M4 票 17）。匯入一律是合併，同步就是「各自匯出快照、匯入對方的檔」，結果和合併的順序無關、重複合併不變（交換律、結合律、冪等，`properties.rs` 有性質測試）。每個條目（（方案, 輸入碼, 詞）、個人 bigram 的一組、英文使用者詞）分兩部分合併：

- **次數（G-Counter）**：每台一格，只有那台會加自己那格；合併時每格逐欄取大，合計是各格相加，所以兩台各選一次就是兩次（排位規則 2 的「選兩次成首選」跨裝置也成立）。格子記用過幾次（`uses`）、整串上屏的累計與「不算的」（一年沒整串上屏後重算、刪除時記下當時的累計），各欄只增不減，逐欄取大就是那台最新的樣子。一年的時限各台各自算（那台最後一次整串上屏的日期）。
- **墓碑**：刪除（撤銷學習、刪自動造詞、刪常用語、刪英文使用者詞、常用語換掉觸發詞時舊觸發詞的計數）記下刪除時的合計次數與日期；合計次數大於它才存活，所以刪除後再用一次就復活，不做永久屏蔽。刪除同時把各台當時的整串上屏累計記成不算的，復活後要再選兩次才成首選。撤銷學習的部分清除（個人 bigram 只清「現在的前一個字詞 → 它」那組，M4 票 16）是逐組的墓碑，別組不受影響。
- **學到的值**（衰減值、tick、觸發詞、寫法）：每次寫入記下當時的合計次數當版本；合併時版本大的留下，同版本照固定的欄位順序挑一個，版本不大於墓碑的（刪除前寫的）丟掉。合計次數只增不減，刪除後再用寫的版本一定比別台刪除前寫的大。
- **tick 只在本機用**：不同台的 tick 是各自的上屏次數，不能比。合併時兩邊的 tick 對齊到較大的一邊、各值往後挪，距「現在」的上屏次數（衰減、規則 2 的 1 萬次期限）不變。
- **墓碑只存雜湊**（協調者 2026-11-12 替使用者決定）：刪掉的條目移到墓碑表，鍵是「種類與各欄」的 SHA-256 前 16 位元組，匯出成 `deleted` 列，不存原文，維持 M3 票 14「刪掉的常用語不留在匯出檔」的保證；合併時拿對方的鍵算同樣的雜湊來比，再用到同一個詞時從墓碑表移回來。
- **清空也同步**（使用者 2026-11-13 決定）：清空學習資料留一個清空記號（代數、日期、裝置 id），代數取看過最大的加一。合併時代數大的那邊整份算數、代數小的整份不收，同代數才逐條合併；一台的資料永遠只屬於一代（收到較新的代數就先清掉自己的），所以不必每列記代數。是代數與逐條合併的字典序，三條律照樣成立。
- **從備份還原**（協調者 2026-11-13 決定）：和匯入（合併）分開的動作。還原留一個新的清空記號（代數取這台與備份較大的加一），再把備份的條目當成之後學到的收進來；是這台的新事件，三條律不受影響，清空前做的備份也還原得回來。
- **墓碑保留一年**：刪除的日期距今超過 365 天就在合併時回收，和學習的時限同一年：回收後才回來的舊快照，裡面刪除前用過的條目最後使用的日期也過了一年，回來也是停用的，不會有害地復活。手動加詞與常用語不受一年時限，刪它們的墓碑不記日期、不回收（同次數時不回收的墓碑最大），否則舊快照會讓刪掉的常用語帶著原文回來。

## Considered Options

- **照 librime 的 `c` 取負**（刪除把次數改成負的、保留絕對值；合併時取絕對值大的，`docs/research/learning-forgetting-sync.md` §1.4）：只要一個整數，但刪除與正值同絕對值時兩邊各自保留自己的符號，**永遠不收斂**，結果取決於誰是本機；墓碑也不回收。次數取大不相加，兩台各選一次只算一次。
- **單一整數取大（不分台）**：簡單、冪等，但兩台各選一次只算一次，違反使用者定的「兩台各選一次也算兩次」。
- **LWW（較晚的時間戳勝）**：要靠牆鐘，殼的時鐘可能錯（M4 票 13 停用不刪也是為了這個），刪除與復活會判錯。版本改用合計次數，不依賴時鐘。
- **墓碑存原文**：檔案看得懂、實作少一張墓碑表，但刪掉的地址、email 一年內仍在匯出檔與 `localStorage`。
- **清空只清這台**（第一版的做法）：清空後再匯入別台的檔，別台有的全部回來，各台要各自清空；使用者 2026-11-13 改成同步。清空時改成對每列留墓碑也不夠：清空時沒看過的別台資料會當成並行使用而存活。
- **向量時鐘的墓碑**（記刪除時看過的每台次數）：能精確分辨「刪除時沒見過的並行使用」，但每列多一組向量；合計次數的寫法只在極少數並行刪除時少帶回一點衰減值，影響只在個人分。

## Consequences

- 匯出檔每列多了各台的次數（編號對到檔頭的裝置表 `#@/device/<n>`，id 空的是不知道哪台：v1、v2 匯入的與殼沒給裝置 id 時學的）、墓碑兩欄與版本；刪掉的條目只剩 `deleted` 列。M4 票 12–16 的 v3 草稿（main 7ad01da）照收，次數記在檔頭的裝置（草稿時代取代匯入過別台的檔時，那批次數同步後會算兩次）；更早的草稿不收。
- 殼必須給每台一個不同的裝置 id（`UserModel::set_device`）；兩台用了同一個 id 時次數取大、少算。
- 上限淘汰（M4 票 13）是這台自己的空間管理，不留墓碑：別台還有那列時合併回來照樣有。
- 清空之後、收到清空記號之前別台學的（時間上在清空之後）也會清掉：代數不依賴牆鐘，核心分不出「清空前」與「同步前」。這是清空同步的固有代價（協調者 2026-11-13 接受），網頁清空鍵旁有說明。清空前做的備份用「匯入」合併不收（代數較小），要用「從備份還原」。
- 退格撤銷（M4 票 15）會把這台自己的格子退回去，是唯一讓格子變小的操作：匯出與合併都讓撤銷紀錄失效（網頁按「匯出學習資料」時呼叫 `expireUndo`），撤銷掉的學習才不會從別台合併回來。
- 刪除時沒見過的別台次數（並行使用）讓條目存活，但那台寫的值版本可能不在墓碑之後而丟掉：條目在、次數照算，衰減值要等那台下次用到才回來。
- 常見的短詞可以拿字典算雜湊，比對出「刪過哪個詞」；地址、email 這類長串猜不到。
- 別台的值以它匯出時的「現在」對齊，快照放了多久核心不知道（只有日期）；同步越頻繁越準。
