# 學習一年沒用就停用、不刪；日期由殼給，不知道就留空

行為由 `crates/qim-core/tests/date.rs`、`learning.rs` 說明；殼的日期契約在 `ARCHITECTURE.md`〈核心對殼〉。

學到的每個條目記最後使用的日期。一年（365 天）沒用的條目停用：不給個人分、不算排位規則 2、3，自動造詞不進 lattice，個人 bigram 與英文使用者詞當作沒學過；手動加詞與常用語一直有效。日期是殼用 `UserModel::set_today` 給的使用者當地日曆日；殼沒給過時學到的條目沒有日期（`None`），時限跳過它們。實體刪除只在條目到上限時淘汰，最舊的（多半就是停用的）先刪。

- **停用不刪**：核心分不出殼給的日期是真的還是時鐘錯了（重開機後亂掉、被改到幾年後）。收到新日期就刪的話，時鐘改回來也救不回；停用的條目在時鐘改回來後恢復作用，一年多前的備份匯入也照收。
- **不寫假日期**：殼漏給日期時寫成某個預設日，之後會被當成很久沒用而停用；留空才安全。
- **條目上限照 LatinIME 的結構**（`docs/research/learning-forgetting-sync.md` §2.3）：分（方案, 輸入碼, 詞）的列加英文使用者詞、個人 bigram 兩個上限（預設 2 萬、3 萬：學完全部公開集合約 1.9 萬列、2.8 萬組，使用者的 Rime 資料約 4,600 條）；到上限的 1.2 倍才清到上限，不必每次學習都淘汰。淘汰先刪沒到出現門檻的，再刪日期最舊的、同一天刪衰減值小的。

## Considered Options

- 過期就刪（LatinIME 在 GC 時移除 300 天沒用的，`docs/research/learning-forgetting-sync.md` §2.2）：時鐘錯了再改回來也救不回。

## Consequences

- 殼必須在第一次學習前、之後每次使用者操作前給今天的日期（過了午夜才不會記成前一天）。
- 英文使用者詞的出現門檻 `UserModel` 不知道英文詞典，詞典有的詞打過一次也算沒到、先被淘汰；要改得讓 `UserModel::merge` 收英文詞典，或在格式裡記「是詞典詞」。
