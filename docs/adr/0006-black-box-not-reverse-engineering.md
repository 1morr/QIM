# 用黑箱測試了解閉源輸入法，不逆向

了解 Gboard、iOS、macOS 輸入法時，只實際打字並讀回畫面（`docs/research/closed-source-imes.md` §4 的測試表），不反編譯、不讀它們的詞庫與模型內容。使用者感受得到的行為黑箱就量得到，對方的碼表和模型又本來就不能放進產品；Google 條款與 Apple 授權也都限制逆向（`docs/research/facts-products.md`），而 QIM 以 Apache-2.0 公開，來源不乾淨的實作以後很難說清楚。開源專案照讀：GPL 專案只取做法和公式，不抄程式碼。

## Considered Options

- 開一個研究里程碑先深讀所有開源專案：第一輪已看過架構，剩下的問題要到做那個功能時才具體，所以改在對應里程碑開工時各讀一次（`docs/roadmap.md`）。
- 逆向閉源程式：可能看到內部做法，但多半用不上，風險也由開源專案長期承擔。

## Consequences

- 看不到閉源產品的內部做法，只能從行為與公開論文推測。
- 黑箱解不開的具體問題逐案問使用者；範圍最多到看檔名、大小與連結關係，不開內容。
