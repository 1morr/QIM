# 佈局用畫布模型，編輯器只寫一份網頁版

佈局不按「排」組織，而是一張畫布：每個按鍵各自記位置、大小、旋轉、形狀和上下層順序，點擊判定放在共用的 `qim-layout`。使用者要能像畫布一樣自由拖動、變形，甚至讓按鍵重疊、亂序；所有查到的開源鍵盤格式都以排為單位、只支援矩形（`docs/research/open-source-imes.md` §4），沿用它們日後要整個重寫，所以 M1 就用畫布模型，參考 Delta skin 的設計尺寸加每鍵 `frame`。編輯器只寫一份網頁版，在各平台主 App 內嵌，因為它是拖放密集的工具，分平台原生各寫一份會讓功能不一致；鍵盤本身仍由各平台原生繪製。

## Considered Options

- 以排為單位再加偏移（FlorisBoard、Trime 的路線）：Gboard 式佈局寫起來簡潔，但重疊與任意位置都要靠例外欄位。改由工具從排列算出預設佈局，得到同樣的整齊。
- 各平台原生編輯器：手感最好，但要寫多份。若內嵌手感不佳，只把有問題的操作改原生。

## Consequences

- `web/editor/` 隨產品發佈，是「網頁 UI 之後會丟」的例外。
- 每個觸控平台殼都要能畫旋轉、多邊形、透明度與重疊。
- 容錯與滑動輸入不能假設有「排」，改用按鍵實際位置算鄰近關係。
