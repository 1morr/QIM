# M4 輸入增強

由 plan §7.5 細化（2026-11-12）。拆票後以票為準；票與本檔衝突時改票或改本檔，並在 progress〈偏差與決定〉記一行。

## 目標

分兩期（使用者 2026-11-12 決定，M4 檢視；審查與成熟做法見 `docs/research/learning-forgetting-sync.md`、`docs/research/spatial-correction-swipe.md`）：

1. 第一期：中文容錯與學習資料。打錯一碼、觸控點偏了，詞與句照樣讀得出來，原樣讀得通的不被改；學習資料會過期、有上限、能撤銷，並定稿跨裝置合併的規則與 v3 格式。做完有期中檢查（`bench`、每鍵延遲、使用者試用）才開第二期。
2. 第二期：英文與譯詞。英文模式自己組字、出建議、可自動修正；觸控有中英鍵與英文鍵盤；欄位類型、智慧標點、句中英文混輸實驗、譯詞資料包、聯想補強。

全部先在網頁做完、Playwright 實打讀回；觸控的功能也要在手機瀏覽器試過。平台殼在 M7 起一次接上。

## 共同規則

- 沿用 M3 的：依賴用 `cargo add` / `npm install` 取當時 stable，與 plan §1.4 不同時同一 commit 更新該表，版本相關 API 先查 context7 或官方文件；新 crate 或新依賴先改 plan §1.3 與 `xtask` 的 `RULES`；命名照 plan §0 與 `GLOSSARY.md`，新名詞（容錯、空間模型、英文使用者詞、墓碑…）在用到的票補進名詞表，換掉「記住的字串」的票同時改名詞表；建置產物與下載的來源不進 git；新增或改動開發指令的票同輪更新 `docs/development.md`；候選每頁 9 個。
- 改核心、排序或資料包的票，在票的 `## Comments` 附 `cargo xtask bench --check` 的前後對照（各集合、依長度分組、翻盤清單）；動到學習的另附 `--learning`。數字變差要說明原因；`--update-baseline` 同一個 commit 寫理由（plan §5.2）。
- 改 lattice、排序或容錯的票另附每鍵延遲（空白與學過的學習資料各一次），要在〈每鍵延遲上限〉內；動到容錯或停鍵層輸入的票另跑 `model-ladder` 的 `neural --split test` 與 `compare`（`bench --check` 守不到重排，plan §2.7）。
- 個人集只報數字與題號，內容不進 repo、commit、票（plan §5.2）。
- 門檻照 M3 的做法在看結果前定，寫明可以改門檻的條件；調參只看 dev 切分，test 與個人集只在設定定案後跑一次報數。
- 空間模型、鄰鍵一律從 `qim-layout` 的按鍵幾何算，不寫死 QWERTY；核心不知道佈局（plan §1.3）。
- 核心不讀系統時間：日期由殼給（`set_today` 這類），測試直接給日期。基準與 Playwright 用固定的日期，時限相關的測試照日期跳。
- 動到網頁的票，除了 Playwright 腳本，再實際操作網頁亂按一輪（組字中夾雜各種鍵、快速連按、切換模式與新開關）；找到的問題先寫成會紅的 Playwright 測試再修。截圖存 `.scratch/m4/evidence/`。新行為的測試在 debug 面板讀得到的，用面板讀回原因（來源、修正、分數），不只讀候選文字。
- 觸控功能在 Playwright 用手機 viewport 加 `tap` 驗；使用者的手機瀏覽器試用集中在期中檢查與收尾票，不阻塞各票。
- 會改寫打出的字或改變候選位置的新行為都有開關，預設值照 brief §7；新開關進 `Options`，網頁設定頁照現有的表加一列。
- 對外格式：學習資料 v3 在 M4 收尾前還沒發佈，M4 的票可以往 v3 加列的種類與欄位，收尾票定稿並寫進 plan §2.4；v1、v2 的匯入一直要收，匯入 v2 的記住的字串轉成已過門檻的英文使用者詞。`Snapshot` 加欄位、新 `PackKind`、佈局的新按鍵動作也是對外介面，設計時先看成熟產品，採用誰的慣例寫在票裡。
- 新資料來源釘進 `data/sources.toml`（版本、sha256、授權、取用的檔案），每個資料包的 `LICENSE`、`NOTICE` 只寫它用到的來源（plan §4）；新資料包加進 `cargo xtask data --verify` 的決定性檢查。
- 實驗放 `scripts/experiments/<名>/`，各有 README（日期、機器與系統、版本、commit、量法、結果表），實驗的 crate 不進 workspace；結論先寫 `docs/research/`，再摘進 brief〈查證過的事實〉並連結。
- 要使用者決定或動手的事（容錯採用門檻、條目上限的數字若超出票的提案、期中試用、付費生成譯詞、推到遠端與建 GitHub release），到了就在該票停下問，不阻塞其他票。

## 每鍵延遲上限

M4 起 `cargo xtask bench --check` 擋每鍵延遲（原生，這台 Mac）；WebAssembly 照舊只報。上限是 M3 同步層的成本門檻（M3 spec〈採用門檻〉），學過的資料另給一組，都比 M3 收尾時的數字留約 7–13 倍的餘裕：容錯與萬用鍵會放大 lattice，倍數級的變慢要擋下來，機器負載的雜訊不該擋。

| 學習資料 | 全部 p95 | 第 20 碼起 p95 | 選開頭一段 p95 | M3 收尾時（全部 / 第 20 碼起 / 選開頭一段） |
| --- | ---: | ---: | ---: | --- |
| 空白（日常 `bench`） | ≤ 1 ms | ≤ 1 ms | ≤ 5 ms | 73 µs / — / 1.29 ms（票 23） |
| 學過（學完全部公開集合的 `UserModel`，量法照 M3 票 12 的 Comments） | ≤ 3 ms | ≤ 3 ms | ≤ 10 ms | 219 µs / 441 µs / 1.58 ms（票 12） |

- 超過時先在負載低時單獨重跑一次，仍超過才算紅。
- 可以改上限的條件：低階機（M8、M9）實量顯示這台 Mac 的預算要收緊，或 brief §9 的每鍵目標改了。不因某張票超過而放寬。

## 容錯採用門檻

票 08 提出，使用者 2026-11-12 確認（照提案），之後的實驗與實作票（09、10）不改它。量法與集合見 plan §5.2、`docs/development.md`〈首選字基準〉；錯誤模型的參數與來源在 `docs/research/typo-bench-models.md`。

基線（不容錯，test 切分，兩個口語語料合計；`bench/baseline.json` 的 `<名>·打錯`、`<名>·觸控`，票 08 在 `6ec152a` 之上量）：

| 集合 | 打錯的題（首選答對） | 沒打錯的題（首選答對） | 修正 |
| --- | --- | --- | --- |
| 含打錯碼（2,638 題） | 937 題（2 題，0.2%） | 1,701 題（773 題，45.4%） | 8,170 次（3.10 次/句） |
| 觸控模擬（2,638 題） | 1,814 題（0 題） | 824 題（388 題，47.1%） | 9,892 次（3.75 次/句） |

主分支之後再改資料包或核心時，各票在開工的 commit 重量基線再比，門檻（增量與上限）不變。

- 打錯集合要多好（兩個口語語料合計）：
  - 含打錯碼：打錯的題首選答對率 ≥ 10%，且整個集合的修正次數比基線少 10% 以上。
  - 觸控模擬：打錯的題首選答對率 ≥ 6%（每題的錯比較多），且修正次數比基線少 10% 以上。
  - 改善的翻好／翻壞要過 McNemar 精確檢定（雙尾）p < 0.05。
  - 四種修正分開判斷：一種修正加進已採用的組合後，打錯的題首選要再多 1.0 點、p < 0.05 才採用；鄰鍵替換看兩種集合，漏碼、多碼、對調看含打錯碼。
- 沒打錯的不退步：維基、口語、有前文的各集合，答錯數增加 ≤ 該集合題數的 0.5%，修正次數增加 ≤ 1%；固定題全過；個人集只報不擋。
- 「原樣正確卻被改錯」：每種打錯集合（兩個語料合計）≤ 1.0%（Fowler 2015 選的工作點）。觸控沒打錯的題較少（分母約 390），判斷時一起看沒打錯的集合那條。
- 延遲：照〈每鍵延遲上限〉，照殼送的按鍵機率量（票 10）。
- 程序：懲罰與空間模型、鄰鍵先驗的參數只在 dev 切分（`dev-typo.tsv`、`dev-touch.tsv` 與 dev 的一般題）調；test 與個人集在設定定案後只跑一次，門檻只看那一次。
- 可以改門檻的條件：期中檢查（票 18）試用後使用者覺得改錯太多或幫不上忙，由使用者決定；錯誤模型依真實打字資料修正後重新產生集合（門檻的增量與上限不變）；brief §4.8 改了。不因某張票沒過而放寬。

第一期：中文容錯與學習資料

- 空間模型：觸控把每次點擊算成各字母的機率（§2.1 的 `Key::Weighted`）：對每個鍵算點擊到它形狀的距離（旋轉、多邊形、橢圓只是距離函式不同），套 2D Gaussian，σ 跟該鍵的大小成比例並有手指精度的下限（VelociTap、FFitts），單位用實體尺寸；重疊的鍵各自算，最上層加成；AOSP 的 `ProximityInfo` 假設矩形與共用尺度，不搬。實體鍵盤由網頁傳 `KeyboardEvent.code`，經 `qim-layout` 依實體鍵盤幾何（各排錯位，含上下排與斜角；libime 只取同排左右，`docs/research/ranking-techniques.md` §5.2）轉成同一種 `Weighted`，以實體鍵位為準、不受配列影響；核心不知道佈局。`Key::parse` 要收得下一組機率。
- 容錯（漏碼、多碼、兩碼對調、鄰鍵替換）：修正只落在詞庫詞或使用者詞的邊上，每條邊最多改一處，單字邊永遠不修（brief §4.8；形碼的容錯沒有任何先例，`docs/research/spatial-correction-swipe.md` §4）。先在 `scripts/experiments/` 做實驗量正確率與延遲，過門檻才進核心。容錯邊帶懲罰進 lattice，懲罰用基準調；「只在無候選時啟動」對速成幾乎不觸發（任兩個字母都是合法碼）。spec 要定：§2.1「各分段的碼接起來就是 `input`」的不變式怎麼改寫、分段顯示哪個字根、學習記修正後的碼、Enter 原樣上屏哪一串。停鍵重排只看沒修正的路徑，或驗收加「沒打錯的集合重排後前 2 名不降」，由票比較後定；容錯的票另跑 `model-ladder` 的 `neural --split test`（`bench --check` 守不到重排，§2.7）。
- 基準：「含打錯碼」集合用和容錯不同、較粗的錯誤模型產生（鄰鍵等機率加漏碼、多碼、對調）；「觸控模擬」集合照 Fowler 2015 在佈局幾何上抽點擊，雜訊和空間模型不同（Goodman 2002：向下、向鍵盤中心偏，x、y 變異不同）；另量「原樣正確卻被改錯」的比例並設上限；懲罰只在 dev 調。
- 萬用鍵：碼表的比對模式，不是容錯（Apple 倉頡的 `Z`）；速成的語意（放首碼或尾碼）由票定、用基準驗。
- 撤銷學習：核心 API 清掉一個候選的學習紀錄，詞庫原有的詞回到原位、再選可重新學，不做永久屏蔽（CyIME 的永久屏蔽被使用者評為偏離預期，`docs/research/cyime.md` §4）；桌面用 Shift+Delete（Rime 慣例）。觸控的手勢跟 M5 重做候選列一起定，長按候選維持字根提示（brief §4.4）。
- 上屏後緊接著按退格，撤銷這次上屏的學習（中英共用，照 librime `memory.cc` 的 `DiscardSession`）：中文撤銷整串上屏次數、衰減值、自動造詞、個人 bigram；英文撤銷剛打完的那個詞。
- 學習時限與上限（使用者 2026-11-12 決定，中英共用；推翻 brief §4.5 原本的「兩次之間隔多久都算」）：殼每次交給核心今天的日期（核心照 §1.3 不讀系統時間）。整串上屏距上一次超過 365 天就從 1 重算；規則 2 是「一年內選兩次」，而且最近一次仍要在 10,000 次上屏內（現有時窗不動）；規則 3 的使用者詞（含自動造詞）一年沒上屏就不再釘在第 2 位、回到一般排序（仍在 lattice）；一年沒用的條目移除（LatinIME 是 300 天）；票 13 實作時使用者改成停用、不刪：超過一年沒用的條目不影響排序但留在資料裡，收到新日期與匯入時都不刪，實體刪除只在到上限時淘汰（殼的時鐘可能錯，改回來要恢復作用）。條目上限照 LatinIME 的結構：到上限的 1.2 倍才清到上限，先刪沒到出現門檻的，再刪最後使用最舊的、同則次數小的；手動加詞與常用語不刪；上限的數字量過學習資料大小後定。基準每集 2 千句調不出一年的時限，時限是產品決定、不由基準調。改 plan §2.4 規則 2、3，附 `bench --learning` 前後對照。
- 英文使用者詞（使用者 2026-11-12 決定，取代「記住的字串」）：照 LatinIME，核心看得到送出去的英文串都學（英文模式上屏、英文直通），不另認 email，數字、電話、卡號照學；不學：無痕、密碼欄、學習關（brief §8、§4.5）。至少 4 個字元才學。出現門檻：英文詞典沒有的串一年內打過 2 次才出（英文建議列與中文組字完整串），中文組字的前綴補完要 3 次、只給最常用的 20 條；詞典有的詞不受門檻，學習只讓它排前。沒到門檻的照樣匯出、同步（不同步的話，手機和電腦各打一次的串在哪一台都不會出現），雜訊靠上限淘汰時最先刪它們。v2 匯入的記住的字串轉成已過門檻。用自己的 tick，不推進個人 bigram 的 tick。
  - 出在哪裡：英文建議列打開頭就補完、照使用頻率排；中文組字打完整串時，規則 4 的英文詞表加上學到的（速成打得出的字母才算），排第 2；中文組字的前綴補完取代現在的規則 5，email 不再特別：誤觸率逐條累加（M3 每條約每 1 萬次組字一次，`scripts/experiments/remembered-prefix/`），所以限 20 條。桌面的英文仍是直通、沒有建議列，桌面學到的只出在中文組字。實作的票改 brief §1.5、§4.7、§7 與 plan §2.1、§2.4 規則 4、5，名詞表換掉「記住的字串」。
- 同步的合併規則與使用者詞庫格式（含刪除墓碑）定稿，放在核心；平台殼之後不改格式，實際傳輸方式跟平台里程碑。學習資料的匯出升 `# qim-userdict v3`（使用者 2026-11-12 同意），匯入照收 v1、v2，匯入改成合併。v3 的規則（使用者 2026-11-12 決定）：每列有明確的種類欄（未知種類略過並警告，已知種類照舊嚴格檢查）與最後使用的日期；檔頭記裝置 id；次數各台分開記、合計時相加（G-Counter：每台只加自己那一格，合併時每格取較大值，結果和順序無關、重複合併不變），所以兩台各選一次也算兩次；刪除用「合計次數大於刪除時的合計次數才存活」，刪除後再用會復活、不做永久屏蔽（librime 的 `c` 取負在同步時不收斂，`docs/research/learning-forgetting-sync.md` §1.4）；墓碑保留期用日期；tick 只在本機用（衰減），合併時換算。網頁沒有傳輸層，兩個瀏覽器設定檔的同步用「各自匯出快照、匯入時合併」驗。寫 ADR，補合併的交換律、結合律、冪等性質測試。

第二期：英文與譯詞

- 開頭先做 Gboard 英文鍵盤的黑箱實測（自動修正的時機、退格還原、連按兩下空白、句首大寫、成對符號），寫到 `docs/research/`；譯詞的來源與授權一起查。
- 英文模式（brief §4.7）：單字預測、自動修正（退格可還原）、Shift 與句首大寫；自動修正與句首自動大寫各有開關、預設關，容錯也有開關、預設開（brief §7），都放進 `Options`。自動修正對原樣讀得通的要保守，照 AOSP 不自動修的條件（含數字、全大寫、email 字元等）；退格還原時不學修正字。核心的英文直通把鍵交還宿主，英文模式要核心自己組字、出建議，是新的組字狀態，寫一份 ADR，一起定：
  - `Snapshot` 加「先刪游標前 N 字再上屏」（例如 `delete_before`），給自動修正還原、連按兩下空白、成對符號用；殼照做，不自己判斷（§1.3）。先查證 iOS `deleteBackward()`、Android `deleteSurroundingText`、macOS IMK `replacementRange` 的行為，寫進 brief §12.3。
  - 英文的切詞：`@`、`.` 這類字元算不算詞內（email 要整串是一個詞，LatinIME 以 `.` 分隔）。
  - 英文資料包改用 aosp-dictionaries 的 experimental 詞典（CC BY 4.0，逐詞頻率與 bigram、含 `z` 開頭的詞，`docs/research/spatial-correction-swipe.md` §6），取代 `scowl-en-us`，同一份也給規則 4；用 `bench` 確認第 2 位不會被多搶；`z` 只在中文組字的比對時濾掉（§4.4）。「預測」包不包括下一個詞由 ADR 定。
- 觸控的中英切換鍵與英文鍵盤（QWERTY 字母頁）：預設觸控佈局加中英鍵（brief §4.4 現在沒有，只有接實體鍵盤才進得了英文）。英文頁與中英鍵做成佈局的頁面與按鍵動作，自訂佈局才能自己決定放不放；英文狀態的建議列只做最小版，沿用現在的候選列，M5 重做候選列時再改。
- 英文建議列：英文使用者詞與英文詞典的前綴補完（上面〈英文使用者詞〉）。
- 欄位類型：email、網址預設英文模式並關自動修正，數字欄開數字頁。
- 智慧標點（可關）：成對符號自動配對（插入一對、游標放中間，還是左右輪流，等 Gboard 實測再定）；英文模式連按兩下空白輸出句點。都用上面的 `delete_before`。數字後半形已在 M1 票 26 做。
- 句中英文混輸實驗（brief §4.7）：英文詞帶懲罰進 lattice，只收拼對的常見詞、不容錯，並設最短長度；純中文集的首選與修正次數不退步才採用，結論寫回 brief。
- 譯詞：繁體與粵語對英文的詞表，來源與授權查不到合用的（CC-CEDICT、CC-Canto 待查是否 share-alike；粵典的英文釋義是非商業條款），再評估自己用 LLM 離線生成（青簡做法）。做成可選資料包（走 M3 的 manifest，加一種 `PackKind`），以繁體原文為鍵、簡體模式查原文，候選旁顯示譯詞，修飾鍵加數字上屏譯詞（青簡：macOS ⌥、Windows Ctrl）；觸控怎麼上屏跟 M5 一起定。
- 聯想補強（M3 票 13 留下，黑箱 T8）：emoji 聯想、空輸入的句首建議、數字標點後的量詞聯想，先評估再做。
