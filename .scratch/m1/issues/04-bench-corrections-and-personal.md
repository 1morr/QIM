# 04: 基準：修正次數、長度分組、翻盤清單、個人集

Status: ready-for-agent

## What to build

基準從「答對幾題」擴成 plan §5.2 的修正成本指標，並加上使用者自己的個人集，讓之後每張票看得出打字要多按幾下、哪幾題翻盤。

- 修正次數（plan §5.2 的模擬：首選接得上就空白，否則選接得上的最長候選，第一頁沒有就翻頁）、每字按鍵數（KSPC）、首選跳動（只回報，不擋）。在 M0 的整串查碼上會很差，數字差沒關係；模擬卡住（翻完都接不上）的處理在本票定。
- 依長度分組（目標字數 1、2、3–4、5–8、9 以上）：正確率與修正次數。
- 翻盤清單：和 baseline 比，列出由錯變對、由對變錯的題目；個人集只列題號。
- `baseline.json` 加修正次數；`--check` 也比修正次數。雙向測試補上「修正次數變多會紅」。
- 個人集：讀 `bench/personal/rime-userdb.txt`（brief §12.2 的三欄格式），取 `c ≥ 1` 的詞，輸入碼用票 01 的轉碼函式從詞轉出（不用 Rime 記下的碼）；報不加權與依 `c` 加權兩種；`bench/personal/baseline.json` 只在本機。檔案不存在時跳過並註明。
- 個人集的內容不寫進 repo、commit、票（spec〈共同規則〉）；輸出只有數字與題號。

## 驗收

- [ ] `cargo xtask bench` 印出各集合的修正次數、KSPC、首選跳動，與依長度分組的表（貼輸出，個人集只有數字）。
- [ ] 翻盤清單：用一個刻意改壞一題的暫存資料或 baseline 示範由對變錯會列出（測試）。
- [ ] `--check` 在修正次數高於 baseline 時紅，有雙向測試。
- [ ] 個人集加權與不加權兩組數字都有；`bench/personal/` 仍被 `.gitignore` 排除，`git status` 乾淨。
- [ ] 沒有個人集檔案時 `bench` 照常跑完。
