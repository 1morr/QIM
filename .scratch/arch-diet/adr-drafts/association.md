# 聯想由詞庫、字級 bigram 與個人 bigram 現算，數字鍵選、空白不選

> 草稿（arch-diet 票 02 從 plan〈核心〉〈介面〉〈聯想〉與〈排序：同一把尺〉搬來），使用者確認後由票 06 編號寫進 `docs/adr/`。行為由 `crates/qim-core/tests/association.rs`、`backspace_undo.rs` 說明，打分寫在 `crates/qim-core/src/association.rs`。

上屏組字之後，候選列換成接下來可能要打的字詞（最多一頁），分數是接上那個聯想的路徑比不接時多出多少，用同一把尺。

- **不另建資料包**：librime-predict 查預先建好的「上一次上屏 → 下一個詞」資料庫；這裡直接由詞庫（補完更長的詞）、字級 bigram、個人 bigram 算。代價是詞庫另依文字排序存一份：約 26 萬詞多約 4 MB 常駐、峰值多約 7 MB，載入多約 20–30 ms。
- **只從分段的邊界補完、不拆開剛上屏的詞**：拆了要扣 γ 又丟 β，很少贏。
- **聯想顯示中的鍵照 macOS 速成**（黑箱 T8，`docs/research/facts-products.md`）：數字鍵 1–9 與點選選聯想、可一直接下去（同 iOS）；空白不選、照打空格（macOS 沒有預選）；Esc 只收起。不學 Microsoft 的 Shift＋數字：實體鍵盤的 Shift＋數字是全形標點；代價是上屏中文後緊接著打數字要先按 Esc（或關掉聯想），同 macOS。
- **退格交還宿主刪字、聯想同時收起，並撤銷這次上屏的學習**（使用者 2026-11-13 定）：偏離 librime-predict 與 Gboard 第一下只收起、第二下才刪字的慣例；只想關聯想用 Esc、點別處或直接打下一個字。
- **聯想的 emoji** 插在前兩個字詞後面（照 macOS 速成：日 → 本、期、🌞）。誤觸：聯想沒有預選、空白不選，只有按數字或點才會選到；代價是原本第 3 位起的字詞往後移、第 7–9 位的擠出這頁（數字鍵 3 選到的從字詞變成 emoji），同 emoji 候選佔第一頁的代價，關「emoji 候選」就沒有。
