# M5 觸控鍵盤與設定

由 roadmap〈M5 觸控鍵盤與設定〉細化（2026-11-18）。拆票後以票為準；票與本檔衝突時改票或改本檔，並在 `docs/decisions.md` 記一條。

## 目標

平台殼開工前，先在網頁把觸控鍵盤做到幾乎完整，使用者在手機瀏覽器確認後各平台照做（使用者 2026-11-12 決定，`ARCHITECTURE.md`〈平台殼〉）。分兩期（使用者 2026-11-17 同意，M4 回顧）：

1. 第一期：盤點 Gboard 與 iOS 內建鍵盤、出設計稿；候選列接到觸控鍵盤頂端，沒有組字時換成工具列；鍵盤內設定頁；調整鍵盤高度；M4 留下的網頁整理。做完由期中票在手機試用，定期界、改第二期的票。
2. 第二期：emoji、文字編輯、剪貼簿面板；空白鍵滑動移游標、英文滑動輸入、評估中文滑動；撤銷學習的觸控手勢；評估句首建議、量詞聯想與英文下一個詞；盤點時使用者勾的其他項目。

全部在網頁做完、Playwright 用手機 viewport 實打讀回，截圖給平台里程碑當對照。

## 範圍（做 / 不做）

### 做

第一期前置（沒有擋，可以平行）：

- 修復票（arch-diet 票 06 的清單，使用者 2026-11-18 同意）：`Session::forget` 的註解讀起來像清掉所有前文後面的個人 bigram；`user/format.rs` 的 `HEADER` 還寫「M4 收尾前還沒定稿」；`word_trigram.rs` 的 `LARGE` 寫常駐 35 MB，iPhone 實測留下 +23.4 MB、峰值 +71.3 MB（`docs/research/ios-feasibility.md`〈詞級 trigram 的記憶體〉）；`verify.rs` 的 `CheckId::Decodes` 註解漏了詞級 trigram、放寬版從沒被解開；舊核心讀到不認得的資料包種類拒絕載入靠 serde、沒有測試，資料包索引只要有一項新種類整份就讀不了，改成略過那一項並警告（使用者 2026-11-18 同意）。
- 文件小票：`web/src/host.ts` 的 `Editable` 旁寫欄位類型的輸入框為什麼用 `textarea`（`type=email`、`number` 的 `input` 沒有 `selectionStart`、`setRangeText`）；`docs/agents/ticket-template.md` 加「新的排序原因要在 `Inspection` 與 debug 面板加一欄、測試讀回」。
- 網頁前置整理（M4 票 31，先做好讓後面的票容易改）：e2e 各 spec 各抄一份的 helper（`ready`、`ui`、`shown`、`place`、讀面板機率）收成共用模組；用完就 `free()` 的寫法收成一種（`withSnapshot`、手寫 try/finally、直接 `.free()` 各有，範圍含 Snapshot 以外的 wasm 物件）；`undoWindow` 也當兩下空白的計時器，改成通用的名字、時限由呼叫端給。

第一期：

- 盤點（第一張會擋人的票）：`orca emulator-android` 在 Gboard 實測觸控鍵盤的全部功能（工具列、各面板、長按、手勢、設定頁的分類與項目、鍵盤高度分幾段），另在 iOS 模擬器對照內建鍵盤，只記 Gboard 沒有的（使用者 2026-11-18 同意）；Gboard 速成的 `z` 鍵行為（M4 票 11，定要不要把「重」改標「＊」）；瀏覽器讀剪貼簿的限制。寫到 `docs/research/`，列成清單請使用者逐項勾要不要，勾完才出設計稿；期界也在這時定。
- 設計稿兩張（`docs/agents/ui.md`，一個畫面一張）：候選列與工具列；鍵盤內設定頁與鍵盤高度。規格照 brief §4.4：直向 390 寬與橫向 844 寬、淺色與深色、照 Gboard 實測的現有鍵盤樣式。
- 候選列接在觸控鍵盤頂端（現在在輸入框下方，和鍵盤隔著工具列與設定區）；沒有組字時同一格換成工具列（Gboard 做法），放設定、emoji、剪貼簿、文字編輯、常用語等入口，入口照盤點勾的。第一期面板還沒做的入口照設計稿處理（隱藏或停用）。
- 鍵盤內設定頁：分類照之後平台 App 的設定（盤點的 Gboard 分類），搬進去的是設定表的 17 列加工具列的數字列、深色、字根提示；觸控鍵盤、debug、欄位選單是測試頁的工具，留在頁面工具列（使用者 2026-11-18 同意）。設定現在不存檔，一重新整理就回預設：開關、外觀與鍵盤高度改成存進 `localStorage`（使用者 2026-11-18 同意）。只搬開關與外觀；常用語、英文使用者詞、詞庫匯入、資料包、學習資料匯入匯出留在頁面上，當作平台的主 App（使用者 2026-11-18 同意）。桌面模式（沒有觸控鍵盤）由頁面工具列上一顆設定鈕打開同一個設定頁（使用者 2026-11-18 同意）。
- 調整鍵盤高度：設定頁的一項，分幾段照盤點；照 Gboard 只改高度、寬度維持全寬，觸控的點擊換算拆成 x、y 兩個比例（使用者 2026-11-18 同意，盤點時確認 Gboard 的行為）。
- M4 留下的觸控殘項：觸控鍵盤靠標籤 `🌐` 認要畫成圖示的鍵、`touch.ts` 另存一份中英狀態（M4 票 23）；地球鍵選單的「點外面收起」只在鍵盤範圍內（M4 票 23）；觸控刪除鍵的退格撤銷只在核心驗過（M4 票 18c）；`z` 鍵標示照盤點。
- M4 留下的英文殘項：觸控點擊的按鍵機率接進英文修正（現在英文容錯不看鍵位鄰近），接上後重量自動修正的 4 倍門檻（M4 票 25）；無痕時殼不給前文，剛聚焦時不知道游標前有沒有字、換行後不句首自動大寫（M4 票 24）。
- debug 面板開著又打過字後，第一次點「無痕」勾選框沒反應（M4 票 16）：在設定頁那張票先寫成會紅的 Playwright 測試再修。
- 期中票：第一期全部做完後跑全部檢查、使用者在手機瀏覽器試用第一期並回覆，依盤點勾的結果增刪改第二期的票，才開第二期。

第二期（現在粗拆，期中票增刪改；使用者 2026-11-18 同意）：

- 面板設計稿三張（emoji、文字編輯、剪貼簿），各自的實作票：emoji 面板（分類、最近用過、搜尋）；文字編輯面板（方向鍵、選取、全選、複製、貼上）；剪貼簿（瀏覽器讀不到系統剪貼簿歷史，範圍照盤點查到的限制）。
- 空白鍵左右滑動移游標。
- 滑動輸入：先讀 FlorisBoard v0.5.2 與 AnySoftKeyboard（`docs/research/facts-products.md`），寫 ADR 定滑動和佈局按鍵自己的 flick 怎麼分（研究建議照青簡的方向扇形，`docs/research/spatial-correction-swipe.md` §5）；英文滑動輸入的解碼用 `qim-layout` 的按鍵幾何，不寫死 QWERTY；形碼的滑行沒有先例，先用模擬軌跡量首選率，再決定做不做畫面，結論寫回 brief。
- 撤銷學習的觸控手勢：能指定任一個候選（`Session::forget` 收任何位置；桌面只清得到首選，釘在第 2 位的自動造詞要靠它，M4 票 16）；長按候選維持字根提示（brief §4.4），手勢另定。簡體模式兩個原文轉成同一個簡體字時候選去重只留第一個、撤銷學習只清得到它（M4 票 16）；簡體去重時聯想的 emoji 從第 3 位變第 2 位（M4 票 30），一起定。
- 評估空輸入的句首建議與數字、標點後的量詞聯想（iOS 速成有，黑箱 T8、T18；M4 票 30）：和沒有組字時的工具列搶同一格；句首建議可用字級 bigram 的句首（`CLAUSE_START`），量詞沒有資料、要另整理量詞表或重訓；桌面上兩者都要在沒有組字時開候選窗。結論寫回 brief。
- 評估英文建議列的下一個詞（空白之後就出建議，Gboard 與 LatinIME 都有；ADR 0008）：要英文 bigram 資料包、英文的個人 bigram 與空白後的建議列。結論寫回 brief。
- 盤點時使用者勾的其他項目，由期中票開票。

### 不做

- 桌面模式的候選列位置不變；實體鍵盤模式（觸控平台接實體鍵盤）的候選列另外定。
- 平台才有的（按鍵音、震動、語音、懸浮鍵盤）只在設定頁留位置與說明。
- 核心給殼的介面整理（`Snapshot.ascii` 改名、模式改列舉等，M4 票 31）：M7 開工時（roadmap〈平台里程碑（M7–M11）〉）。
- 佈局編輯器、單手佈局：M6。
- 資料管理（常用語、使用者詞、匯入匯出、資料包）搬進鍵盤設定頁。

## 共同規則

- 新畫面或改版面的票，先有使用者確認過的 `docs/design/` 定稿（`docs/agents/ui.md`）；實作照定稿，要偏離先問使用者。觸控行為以 Gboard 實測為準，外觀與互動細節用 `impeccable:impeccable`。
- 動到網頁的票：Playwright 用手機 viewport（390 寬，橫向 844 寬）加 `tap` 讀回，截圖存 `.scratch/m5/evidence/`；除了腳本再實際操作亂按一輪（組字中夾雜各種鍵、快速連按、開關面板與設定、切中英與深色、橫向），找到的問題先寫成會紅的 Playwright 測試再修。e2e 用票 03 的共用 helper。
- 會改寫打出的字或改變候選位置的新行為都有開關，預設值照 brief §7，進鍵盤內設定頁。
- 改核心、排序或資料包的票，在票的 `## Comments` 附 `cargo xtask bench --check` 的前後對照；動到學習的另附 `--learning`；改 lattice 或排序的另附每鍵延遲（`docs/development.md`〈每鍵延遲〉）。
- 評估票先定門檻再看結果，調參只看 dev 切分；結論寫回 brief，採用的話由期中票或驗收票前開實作票。
- 依賴用 `npm install` / `cargo add` 取當時 stable，版本相關 API 先查 context7 或官方文件；新依賴同一 commit 更新 `ARCHITECTURE.md`〈主要依賴〉。命名照 `GLOSSARY.md`，新名詞（工具列、設定頁的分類、滑動輸入）在用到的票補進名詞表。
- 對外介面（`Snapshot` 加欄位、佈局的新按鍵動作、新 `PackKind`）設計前先看成熟產品，採用誰的慣例寫在票裡。
- 要使用者決定或動手的事（盤點清單、設計稿、期中試用），到了就在該票停下問，不阻塞其他票。

## 驗收

### Agent 驗

- Playwright 用 390 寬與 844 寬讀回：候選列的下緣貼著觸控鍵盤上緣；清空組字後同一格是工具列；工具列的每個入口開得了；截圖淺色、深色各一張存 `.scratch/m5/evidence/`。
- 從工具列開設定頁，每一個開關改了會生效（至少：關聯想後不出聯想、開數字列後多一排數字、深色切換、鍵盤高度換段後鍵盤高度變）；頁面上不再有搬走的那 20 項（設定表 17 列、數字列、深色、字根提示）；重新整理後設定還在；桌面模式的設定鈕開同一個設定頁。
- M4 留下的各條各有會紅過的測試或量到的數字（4 倍門檻重量的結果寫在票上）。
- 第二期做的面板、滑動、手勢各有 Playwright 讀回；評估票的結論寫回 brief。
- `cargo xtask check` 全套綠燈；`cargo xtask bench --check` 沒有翻盤。

### 使用者試

- 第一期（期中票）：在手機瀏覽器開網頁（`docs/development.md`〈網頁〉，區網開給手機），試候選列與工具列、設定頁、鍵盤高度，回覆同意才開第二期。
- 第二期（驗收票）：在手機瀏覽器試面板、空白鍵移游標、滑動輸入、撤銷學習手勢；另在電腦瀏覽器確認桌面模式的設定鈕。回覆同意後才封存（開工前 roadmap 寫的完成標準）。
