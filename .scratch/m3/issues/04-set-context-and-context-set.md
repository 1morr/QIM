## What to build

核心收得到輸入框的前文，連打的第一個字不再只用 unigram；用新的基準集合證明這有用。

- `Session::set_context(before: &str)`（plan §2.1）：lattice 開頭的字用前文最後一字的 bigram；前文裡不在連打字集的字（英文、標點、數字）怎麼處理在票內定，寫回 plan §2.3。無痕模式下核心不用前文（brief §8：不讀上下文）。
- 同一個機制：選開頭一段後，剩下輸入碼的第一個字接選定分段的最後一字（M1 票 21 的現狀由性質測試鎖住，改測試並寫回 plan §2.1、§2.3）。
- 首選字基準加「有前文」的集合：`cargo xtask data` 從語料的 test 切分取連續句子，前一兩句當前文、最後一句轉速成碼（plan §5.2 表格加一列）；基準報告同一批題給前文與不給前文並列；設 baseline。

## Comments

### 2026-11-11 實作（開工 `4bcee1c`）

**前文的規則（寫回 plan §2.3）**：前文以字結尾時接那個字的 bigram；以標點、空白、符號結尾，或是空的（輸入框開頭）時接句首 `CLAUSE_START`；結尾的字沒有統計（英文、數字、罕用字）、沒給過前文、無痕時用 unigram。選開頭一段或改選某一段後，剩下的輸入碼接最後一個選定分段的最後一字（不檢查統計，和 lattice 裡路徑的下一段相同）。目前分段的候選照舊和單打那個碼相同，不接前一段（plan §2.1 寫明）。

**先試過、不採用：略過結尾的標點，接上一句的最後一字。**「有前文」集合給前文反而比不給差，四個語料都是：

| 語料 | 答錯（給 / 不給） | 修正（給 / 不給） |
| --- | ---: | ---: |
| yue-wiki | 591 / 574 | 2328 / 2300 |
| zh-wiki | 570 / 559 | 2195 / 2188 |
| common-voice-yue | 215 / 205 | 681 / 655 |
| hkcancor | 469 / 465 | 1822 / 1801 |

bigram 只在句內訓練（切句在每個非字母數字處），跨標點接上一句的字沒有根據。改成句首：bigram 訓練時每句的第一字接在 `CLAUSE_START`（U+0002）後面，算成一列（plan §4.3），它的次數不進字次數、`N1+(•w)` 與 `D`，其他字的機率不變（四個舊集合的數字和改前相同可證）。資料包格式不變，bigram 資料包 sha256 `9e393a0a457d` → `dfa21786b886`，句首留下 6,920 字。
